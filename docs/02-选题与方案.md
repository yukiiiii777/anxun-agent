# 02 · 选题与方案

> 结论先行：**骨架是工厂安全巡检，感知任务从「火灾/烟雾检测」换成「PPE 穿戴检测」。**
> 这一换，把技术风险从「高」降到「低」，其他部分一个字都不用动。

---

## 一、先看结论

厂区安全巡检这条链路天生就是完整闭环：

```
发现问题 → 判断等级 → 派人整改 → 复查归档
```

它不是「把大模型套个聊天框」，而是一条有起点、有终点、有责任人的业务流程。评委看三段就能明白你在解决什么。

更要紧的是**演示性**。校赛是通讯评审，评委看的是 6 分钟视频。有摄像头画面、有告警弹出、有工单生成的作品，和只有对话框一问一答的作品，观感完全不在一个量级。

这是三个候选方案里唯一一个「**有画面**」的。

---

## 二、为什么换掉火灾检测

### 2.1 不是因为做不了

我们**能训练模型**，双卡流程是通的（软件杯 A7 赛道跑过火灾检测）。真正的原因是**任务类型选错了**。

### 2.2 语义判断 vs 存在性判断

| 对比项 | 火灾 / 烟雾检测 | PPE 穿戴检测 |
|---|---|---|
| **任务本质** | 语义判断——「这像不像火」 | 存在性判断——「头上有没有安全帽」 |
| **干扰源** | 蒸汽、粉尘反光、夕阳、红色物料、焊接火花，都能骗过模型，而这些干扰在工业现场到处都是 | 遮挡、光照不足。干扰明确，可用数据增强针对性解决 |
| **精度天花板** | 受场景分布影响大，换一个厂区性能就掉，泛化难 | 类别少、形态稳定、边界清晰，公开数据集充足，精度容易做上去且稳定 |
| **演示风险** | 现场光线一变就可能漏检，录屏最容易翻车 | 现场拍几段就能稳定出结果，录几遍都一致 |
| **法规刚性** | 消防安全检查，但不归安全员日常考核 | 《安全生产法》明确要求提供符合标准的个体防护装备并监督佩戴，**是安全检查的必查项** |

### 2.3 答辩话术（这段话很值钱）

> 「我们一开始做的是火焰和烟雾检测，后来放弃了。原因是火焰检测回答的是『这像不像火』——这是一个语义问题，蒸汽、粉尘反光、红色物料都能造成误报，在真实厂区里误报率高到无法使用。
>
> 我们换成 PPE 穿戴检测，回答的是『头上有没有安全帽』——这是一个存在性问题，有明确答案，模型可以做到稳定可靠。
>
> 在工业场景里，**宁可做一个可靠的小任务，也不做一个不可靠的大任务**。」

这段话同时展示了三件事：你做过、你试错过、你懂什么问题该用什么技术。

**主动说出放弃过什么，比吹自己做成过什么更有说服力。**

## 三、痛点为什么成立

| 痛点 | 具体表现 | 可论证的抓手 |
|---|---|---|
| **法规刚性、执行虚化** | 《安全生产法》要求生产经营单位为从业人员提供符合国家标准的劳动防护用品，并监督、教育其正确佩戴使用。但中小厂实际靠班组长目视、靠检查前突击提醒 | 法规条款可直接进知识库，成为 Agent 判断依据 |
| **人工盯不住** | 一个安全员管几个车间，无法全天候覆盖；工人见到检查人员才戴，人一走就摘——这是安全管理里公认的老问题 | 「被检查时的合规率」与「真实合规率」的差距，可量化 |
| **隐患闭环断裂** | 发现了、记录了、没人整改，下次还是同一批人同一批问题 | 闭环时长是可量化指标，最容易出效果图 |
| **记录造假与追溯难** | 纸质巡检表事后补填是行业公开的秘密，出了事故无法还原当时状态 | Agent 自动留痕，时间戳与画面证据绑定 |

## 四、系统架构：五个 Agent

按业务流程拆角色，职责单一、输入输出明确。

| Agent | 职责 | 关键设计（答辩讲这个） |
|---|---|---|
| **① 巡检规划** | 根据厂区平面图、历史违规热区、当班班组，生成当日巡检路线与重点点位 | 风险加权覆盖：历史高发点位加密巡查，不是平均用力 |
| **② 视觉感知** | 检测画面中的安全帽、反光背心、防护眼镜佩戴情况，输出带置信度的合规判定 | **护城河**。模型作为 Agent 的原生 tool，不是外挂 |
| **③ 隐患研判** | 对视觉结果做二次判断：是否误报、违规等级、是否需要立即停工处置 | 用风险矩阵（可能性 × 后果严重度）分级，**不让大模型拍脑袋** |
| **④ 工单闭环** | 生成整改工单、指派责任人、设定时限、超时升级、复查归档 | PDCA 闭环，管理学语言，评委听得懂 |
| **⑤ 合规问答** | RAG 检索安全生产法规与标准，给出整改依据条款原文 | 每条结论「有出处」，这是可信度的来源 |

### 一个可选增强点

如果时间够，在感知层加一条「**通道占用检测**」——消防通道被货物堵塞是安全检查的高频扣分项，用框检测做区域占用判断，几乎不增加工作量。它和 PPE 共用同一个检测模型框架，等于一个模型覆盖两类隐患。

> 当前状态：**不做**。时间不够，先保 ②③④。

### 砍功能顺序

1. 先砍 **⑤ 合规问答**
2. 再砍 **① 巡检规划**
3. **保留 ② 感知 + ③ 研判 + ④ 工单**

这三项是故事的骨架，缺了就不成立。

## 五、数据与知识库

官方在这一章给 2–4 页，明确要求说明数据渠道的「**权威性与时效性**」。这一章写实，分数就稳。

### 5.1 数据来源（三个渠道）

| 序 | 来源 | 类型 | 怎么用 |
|---|---|---|---|
| 1 | 公开安全帽 / PPE 检测数据集 | 学术公开数据集 | 安全帽检测是 CV 领域成熟公开任务，数据量大、标注规范，作训练基座。**具体数据集名称与出处需核实并在 PPT 注明** |
| 2 | 安全帽专项公开集 | 学术公开数据集（MIT） | `toborobot/Safety-helmet-dataset`，4916 训练 / 1413 验证，平均框面积 1.9% 与本项目小目标同构。本项目取 1600 张，与源一混成 1300 张训练集 |
| 3 | 安全生产法规与标准 | 政府规范性文件 | 《安全生产法》、GB 2811 安全帽、GB 39800 个体防护装备配备规范等，构成知识库。**版本与条款号需逐条核实** |

> **诚实原则**：数据集名称、样本量、引用出处，提交前必须能指认到具体来源。
> 宁可只写两个渠道，不要写一个查不到的——官方要求 2–3 个，两个合规。

### 5.2 知识库四层

- **法规层**：《安全生产法》相关条款、地方安全生产条例
- **标准层**：GB 2811 安全帽、GB 39800 个体防护装备配备规范、各行业劳保用品配备要求
- **操作层**：各岗位应配备的防护品类、正确佩戴方式
- **经验层**：历史违规记录、整改案例、事故通报

### 5.3 预处理流程

```
原始视频 → 抽帧去重 → 标注 → 针对性增强（暗光/遮挡）→ 训练与验证 → 推理服务化
```

文本侧：法规 PDF 解析 → **按条款切分（保留条款号）** → 向量化 → 检索。

> 按条款切分保证检索结果是完整条款，不会断章取义——这个细节写进 PPT，是「预处理专业性」的直接体现。

**增强策略要有针对性**：暗光增强、模拟遮挡、多角度翻转。不要用通用增强套餐，要说清楚每种增强针对的是哪个现场问题——这体现你真的下过现场。

详见 [`04-数据与模型.md`](04-数据与模型.md)。

## 六、创新性：官方加分页怎么填

### 创新点一：感知闭环

行业通病是 Agent 只有「语言」，没有「眼睛」，只能靠人喂数据。本作品把检测模型作为 Agent 的原生感知工具，形成「看得见 → 判得准 → 落得下」的完整链路，并给出误报率实测数据佐证。

### 创新点二：定级有据

隐患等级不由大模型自由发挥，而是「**风险矩阵打分 + 法规条款映射**」双重约束。既避免 LLM 幻觉导致定级随意，又让每条结论可追溯到具体条款。

### 独特视角（跨学科）

> 安全工程的风险矩阵 × 计算机视觉的检测能力 × 管理学的 PDCA 闭环。

三层学科语言在一个系统里对齐，正好对应大赛「横向复合型人才」的选拔取向。

**这一段要写成研究贡献的口吻，不要写成宣传语。**

## 七、应用结果呈现

官方硬要求：至少 3 个提示词示例及输出，并提供 Agent 智能体网址链接。

### 7.1 三个必演示的提示词

| 序 | 提示词 | 要展示什么 |
|---|---|---|
| 1 | 「调出今天上午 3 号车间东侧通道的巡检记录，有没有隐患？」 | 检索真实巡检数据，给带证据的结论 |
| 2 | 「这个画面里谁没戴安全帽？判定依据是什么？」 | **最关键**：视觉判定 + 置信度 + 法规条款溯源 |
| 3 | 「三号车间连续三天出现未戴安全帽，生成整改工单并给出建议」 | 趋势识别 + 工单闭环，体现落地性 |
