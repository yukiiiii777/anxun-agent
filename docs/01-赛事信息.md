## 二、赛道与赛制

### 2.1 通用赛道（我们走这条）

三级赛制，**不得跨级**：

```
校赛  →  区域赛  →  全国总决赛
```

| 阶段 | 时间 | 说明 |
|---|---|---|
| 报名 + 缴费 + 作品提交 | **截至 2026-11-10 24:00** | 三者同一死线 |
| 校赛评审 | 2026-11-11 ~ 11-20 | 通讯评审为主，看提交材料 |
| 区域赛 | 2026-11-21 ~ 12-11 | 上海赛区 |
| 全国总决赛 | 2026-12-25 ~ 12-27 | 现场答辩 |

⚠️ **关键前提**：必须通过校赛才能进区域赛。本校若不组织校赛，需找赛区确认兜底方案（见 [`08-报名事项.md`](08-报名事项.md)）。

### 2.2 专项赛道

二级赛制，**不设校赛**，直接区域赛 → 总决赛。如通用赛道走不通，这是备选路径。

## 三、命题形式

官方赛题不是完全自主命题，而是：

```
5 道常规赛题（指定领域 + 指定要求） + 1 道开放赛题 + 指定开发平台
```

我们走**制造领域 · 开放赛题**方向，自主命题为「厂区安全巡检多智能体系统」。

> 这一点很重要：评委不是在评「你有没有做出一个炫酷的 AI」，而是在评「你在给定领域里，用 AI 解决了一个什么样的真实问题」。

---

## 四、评分维度（六个章节 = 六项评分）

官方对 PPT 的章节要求，**就是评分维度**。逐条对齐，不要自由发挥：

| # | 章节 | 评分关注点 | 我们的对应页 |
|---|---|---|---|
| 1 | 作品背景与说明 | 团队分工、一句话说清做什么、**参考来源单列** | PPT 02–03 |
| 2 | 数据收集与处理 | **≥2 个渠道**，说明权威性与时效性；有预处理流程图 | PPT 04–07 |
| 3 | 分析过程 | 方法选择依据；**思维导图形式**（官方点名） | PPT 08–09 |
| 4 | 创新性与独特视角 | 1–2 个创新点 + 跨学科视角 | PPT 13 |
| 5 | 结果解释与建议 | 结果价值、2–3 条不足与建议、风险识别与应对 | PPT 14–17 |
| 6 | 应用结果呈现 | 对话界面截图 + 提示词 + **可访问链接** | PPT 18–19 |

### ⚠️ 两条硬性要求

1. **必须提供 Agent 可访问的网址链接**——没有可访问链接就是零分作品
2. **至少 3 个提示词示例及对应输出**——截图或文字均可，但要能复现

## 五、格式硬限

| 项 | 限制 | 备注 |
|---|---|---|
| PPT | ≤ 20 页，16:9，≤ 50 MB | 超页数直接扣分 |
| 视频 | MP4，≤ 6 分钟，≤ 300 MB | 「不超过」不是「必须满」 |
| 提交包 | **单个压缩包**，≤ 200 MB | 不接受多文件上传 |
| 命名 | `命题领域-学校-队长姓名-作品名称` | 例：`制造-上海中侨职业技术大学-张璟瑜-安巡Agent` |

> 压缩包及文件命名仍按官方命名格式保留学校与队长姓名，两者不矛盾。
> 本次成品已于 2026-11-10 全量清除并扫描零命中（20 页页脚、封面、链接说明、视频旁白）。

**只接受单个压缩包，且以最后一次上传覆盖前次。** 11-10 晚上系统拥堵、上传失败没有任何补救通道。

## 六、平台要求

| 路线 | 说明 |
|---|---|
| 扣子 / Coze（本方案主用） | 1 天能出可公开访问链接，插件机制可挂视觉 API |
| 京东云 JoyCode（本届官方平台） | 官方支撑，免费提供编程与大模型调用；前端搭建成本更高 |

**本校不强制 JoyCode**，锁定扣子路线。

但架构上做了防迁移设计：检测模型封装成独立 HTTP API，业务逻辑写在提示词与接口里。若后续赛区强制 JoyCode，只换界面，2 天可迁完。
