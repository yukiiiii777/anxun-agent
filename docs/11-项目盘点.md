## 五、今晚必须做的三个决定

### 决定 1：阈值统一到哪一套

**建议：统一到 B（techline 实测配置 0.30 / 0.20 / 0.90）。**

理由：报出去的数字必须能当场复现。`evaluate_real.py` 跑出来只能是 B。

代价：`demo.py` 的四态演示会变——P2（0.52）从「待复核」变成「已佩戴」，四态展示只剩三态。

**两个选择：**

| 方案 | 做法 | 后果 |
|---|---|---|
| **B1 改 demo**（推荐） | 把 `src/anxun/rules_engine.py` 阈值同步为 B，重跑 `demo.py`，重新截四态图 | 一致，但招牌镜头「待复核」没了 |
| **B2 标注差异** | 保留 A 的 demo，在 PPT/README 明确写「演示用保守配置 0.6 / 0.4，实测配置 0.3 / 0.2」 | 保住四态演示，但要能解释「为什么演示用更严的配置」（答案：演示要展示保护机制，生产要降漏报） |

我倾向 **B2**：改代码有风险（会动到队友已验收的东西），而「演示用保守配置」本身是一个说得通的工程选择——**严配置看得见保护机制，松配置降漏报，两者服务于不同目的**。但必须到处都写清楚。

### 决定 2：两个仓库怎么办

| 方案 | 做法 | 代价 |
|---|---|---|
| **合一个**（推荐） | 把 techline 从主仓库移出，主仓库只留 `src/` + `docs/`；技术线只保留 `Euphoria-tender` 那个仓 | 主仓库瘦到 ~2 MB；但要在 README 写清「技术线在另一个仓」 |
| 保留双仓 | 承认两个仓都是正式仓，定期手工同步 | 已经证明会不一致 |

**无论选哪个，提交包都要重新组织**——不能把 128 MB 的仓库直接打包。
