# 07 · 分工与计划

> 3 个人，10 天（10/31 → 11/08 提交）。
> **分工原则：按交付物分，不按环节分。**

---

## 一、先看关键路径

36 项任务里，只有一条链是断了就全盘崩的：

```
数据 → 模型 → 指标 → PPT 第 11 页 / 视频演示段
```

这条链上，**数据卡一天，后面全部顺延一天**。

而 PPT 和视频只能等指标和截图出来才能做——所以前 4 天必须把模型跑出结果，不能拖到后面。

这就是为什么**数据采集安排在第 1 天，而且是三个人一起上**。这不是某个人的活，是全队的第一优先级。

## 三、为什么这么分

**按「交付物」分，不按「环节」分。** 每个人从头到尾负责一类东西，交接点少，责任清楚。

### 最怕的分法

> 「你做模型我做 PPT 最后拼起来」

中间没有交接标准，最后一定对不上——做模型的人不知道 PPT 要什么数字，做 PPT 的人拿到数字不知道放在哪一页。

### 现在的分法解决了什么

每个人**知道自己在给谁做东西**：

- 队长知道队友 B 需要「四个数字 + 两张图」
- 队友 B 知道自己要等的就是那四个数字
- 队友 A 知道自己交的链接必须「打开就能演示完整链路」

---

## 四、三个交接点

只有三个，必须按标准交。对方拿到后要能**直接干活**，不是拿到一堆需要再问的东西。

| 交接 | 从 → 到 | 对方拿到后必须能做什么 |
|---|---|---|
| 数据 → 模型 | 全队 → 队长 | 执行一条命令就能开训 |
| 模型指标 → PPT | 队长 → 队友 B | 四个数字 + 两张图，直接填进第 11 页 |
| Agent 链接 → 视频 | 队友 A → 队长 | 打开就能演示完整链路 |

## 七、协作规则

### 7.1 文件命名

| 类型 | 命名 | 示例 |
|---|---|---|
| 代码 | 按目录，不改名 | `src/anxun/train_yolo.py` |
| 数据 | `来源_场景_序号` | `self_workshop-a_0031.jpg` |
| 图表 | `图_用途_版本` | `chart_混淆矩阵_v2.png` |
| 文档 | `类型_版本_日期` | `PPT_v3_1107.pptx` |

**铁律：不要出现「最终版」「最终版2」「真的最终版」。** 用版本号，最新的一版永远是最新日期。

### 7.2 每日站会（10 分钟，固定时间）

每人回答三句，不许展开：

1. 昨天交付了什么（**对着任务编号说**）
2. 今天交付什么（任务编号 + 截止时间）
3. 卡在哪（卡住就说，不要自己硬扛一天）

### 7.3 提交规范

见 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)。核心就一条：commit message 要说得清做了什么。

### 砍功能顺序

万一时间不够，按这个顺序砍：

1. 先砍 **⑤ 合规问答**
2. 再砍 **① 巡检规划**
3. **保留 ② 感知 + ③ 研判 + ④ 工单**

这三项是故事的骨架，缺了就不成立。前两项属于锦上添花，砍掉照样是完整作品。
