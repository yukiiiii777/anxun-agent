# 04 · 数据与模型

> 这一章的重点是**指标能报得出来、报得诚实**。
> 评委不会追问 mAP 小数点，但一定会问「误报怎么办」。

---

## 一、类别设计

| 类别 | 优先级 | 说明 |
|---|---|---|
| `person` | **必须** | 人员基准框，所有判定都以它为参照 |
| `helmet` | **必须** | 安全帽，核心判定对象 |
| `vest` | 建议 | 反光背心，扩展判定维度 |
| `goggles` | **规划中** | 防护眼镜。目标小、标注成本高——**当前未实现**：无数据、无权重。对外表述一律按三类，不提「四类检测」 |

**三类落地，goggles 预留。** 业务判定只认 `person + helmet + vest` 三类；`person + helmet` 两类就能撑起完整演示，不要一开始铺太大。

> **v3.0.0 的交付权重是五类**：在 `person / helmet / vest` 之外多了 `no-helmet` / `no-vest`
> 两个**反向证据类**——模型直接告诉你「这里有个裸头 / 这里没穿背心」，比「找不到就算没戴」可靠。
> 类别顺序是 `helmet, no-helmet, no-vest, person, vest`（见 `techline-v3.0.0/models/config.json`）。
> 下面这份 `ppe.yaml` 是三类的训练配置，自己从头训模型时才用它。

类别顺序固定（写死在 `data/ppe.yaml`）：

```yaml
path: ./data/ppe
train: images/train
val: images/val
names:
  0: person
  1: helmet
  2: vest
# goggles 预留，未启用（见上表）
```

> 顺序错了模型会学成反的，而且不报错——这是最容易踩的坑。

## 二、数据来源

### 2.1 三个渠道

| 序 | 渠道 | 量级目标 | 作用 |
|---|---|---|---|
| 1 | 公开安全帽 / PPE 检测数据集 | 撑主干 | 保证泛化，标注规范 |
| 2 | 自采厂区场景 | **≥300 张** | 解决分布偏移，让「自采」这件事站得住 |
| 3 | 法规与标准 PDF | — | 知识库，不是训练数据 |

### 2.2 公开数据集选型要求

- 标注格式能转 YOLO（或至少能拿到 bbox）
- 类别名能对齐 `person / helmet / vest`
- 有明确出处（论文 / 竞赛 / 官方发布），**PPT 上要能写出名字**
- 许可证允许学术使用

## 三、自采数据：拍什么

### 3.1 采集清单

| 维度 | 要求 | 为什么 |
|---|---|---|
| **佩戴状态** | 戴帽 / 不戴帽 / 帽子拿在手上 / 帽子反戴 | 覆盖真实违规形态，不只是「有/无」 |
| **视角** | 正面 / 侧面 / 背面 / 45° | 摄像头不会都装在正前方 |
| **距离** | 近（<5m）/ 中（5–15m）/ 远（>15m） | 远距离小目标是误报主要来源 |
| **光照** | 白天自然光 / 室内灯光 / 逆光 / 弱光 | 车间光线极不均匀 |
| **遮挡** | 单人 / 多人重叠 / 被设备遮挡一部分 | 真实场景的常态 |
| **人员** | ≥3 人，不同身高体型 | 避免模型学到「某个人」而不是「安全帽」 |

### 3.2 数量分配

```
总计 ≥300 张
├─ 戴帽            120 张（40%）
├─ 不戴帽          120 张（40%）
├─ 手持/反戴等异常  30 张（10%）
└─ 空场景/设备特写  30 张（10%）← 这是负样本，测误报率要用
```

> 那 30 张「空场景/设备特写」很多人不拍，但它们是测误报率的关键。

### 3.3 命名规则

```
来源_场景_序号.jpg

self_workshop-a_0031.jpg
self_outdoor-gate_0007.jpg
pub_shwd_12450.jpg
```

**不要**用手机默认的 `IMG_20261101_093012.jpg`——三个人拍完混在一起没法追溯来源。

## 四、标注规范

### 4.1 规则

- 格式：YOLO txt，每行 `cls cx cy w h`（全部归一化到 0–1）
- **`person` 框要包住整个可见人体**，被裁掉的部位不算
- **`helmet` 框只包安全帽本体**，不含头部和头发
- **遮挡超过 70% 的目标不标**（标了反而污染）
- 边界框贴紧目标边缘，不要留大边距

### 4.2 一个特殊约定

「帽子拿在手上」这种情况，**标 `helmet`（框住手上的帽子），但人的头部区域没有装备框**。这样规则引擎会自动判「未佩戴」——正确。

### 4.3 标注工具

用 LabelImg / Label Studio / X-AnyLabeling 都行。**别手写 txt**，10 张就开始出错。

## 五、数据划分（最容易做错的一步）

### 5.1 规则

```
train : val = 8 : 2
```

### 5.2 铁律：按视频划分，不按帧划分

如果从同一段视频抽了 100 帧，随机打散分到 train 和 val，那么验证集里会有大量「和训练集几乎一样的图」。

结果：**mAP 虚高 10–20 个点**，现场一用就崩。

正确做法：

```
视频 A（120 帧）→ 全部进 train
视频 B（80 帧） → 全部进 val
同一视频的帧不允许跨集
```

**验收标准（任务 B6）**：能说清「val 集来自哪几段视频」，且这些视频没有帧出现在 train 里。

## 六、数据增强：每种都对应一个现场问题

这是体现「你下过现场」的地方。

| 增强方式 | 针对的现场问题 | 怎么做 |
|---|---|---|
| 亮度 / 对比度扰动 | 车间光线不均、逆光、夜间 | Gamma 变换 + 直方图均衡，模拟弱光 |
| 随机遮挡 | 设备遮挡、多人重叠 | Random Erasing，遮挡比例 10–30% |
| 多角度翻转 + 旋转 | 摄像头安装角度不同 | 水平 / 垂直翻转 + 小角度旋转 |
| 尺度缩放 | 远近不同的监控距离 | 随机缩放 + Mosaic |
| 运动模糊 | 人员走动造成拖影 | 运动模糊核，低概率施加 |

### PPT 上要这样写

> ✅ 「针对车间逆光场景，采用 Gamma 变换模拟弱光；针对多人遮挡，采用 Random Erasing 遮挡 10–30%。」
>
> ❌ 「我们做了数据增强。」

**说出每种增强对应哪个现场问题，证明你下过现场；只说做了增强，证明你会调库。**

`train_yolo.py` 里每一行增强参数都写了注释对应哪个现场问题，照着写就行。

## 七、训练

### 7.1 命令

```bash
cd src/anxun
pip install -r requirements.txt

# 小显存先跑通（先确认流程通，不追求指标）
python train_yolo.py --device 0 --imgsz 480 --batch 16 --model yolo11n.pt

# 正式训练（双卡）
python train_yolo.py --device 0,1 --batch 32 --model yolo11s.pt

# 断点续训
python train_yolo.py --resume
```

### 7.2 参数说明

| 参数 | 建议值 | 说明 |
|---|---|---|
| `--model` | `yolo11s.pt` | n 太小精度不够，m 太大训不完。s 是性价比点 |
| `--imgsz` | `640` | 480 是小显存兜底，640 是精度与速度的平衡 |
| `--batch` | `32`（双卡）/ `16`（单卡） | 显存不够就砍这个 |
| `--device` | `0,1` | 双卡并行 |
| `--epochs` | 100 起 | 小数据集可以到 150–200 |

### 7.3 训练完看什么

脚本会自动打印四个数：

```
mAP@0.5 / mAP@0.5:0.95 / Precision / Recall / 单帧耗时
```

这四个数是 PPT 第 11 页的核心内容。

`runs/ppe/` 下的混淆矩阵、PR 曲线、训练曲线图，**直接可用于 PPT**。

## 八、指标口径

### 8.1 目标值

| 指标 | 目标 | 为什么重要 |
|---|---|---|
| mAP@0.5 | **≥ 0.85** | 常规检测指标，说明模型可用 |
| 误报率 | **≤ 10%** | **比 mAP 更该强调**——工业场景误报会让人直接关掉告警 |
| 漏报率 | **≤ 5%** | 安全场景漏报后果更严重，要主动说 |
| 单帧推理耗时 | **≤ 50 ms** | 证明能做实时，不是离线跑批 |

> ❌ **不要报 99% 这种数字。** 工业检测报 99% 反而让评委怀疑你不懂现场。
> 报一个真实但不完美、并能解释误差来源的数字，可信度高得多。

### 8.2 误报率怎么测

准备一批**不含违规**的负样本图：

- 正常戴帽的工人（各角度、各光照）
- 空场景（车间、通道、设备）
- 设备特写（圆形物体、黄色物体等容易误检的）

```
误报率 = 被判为「未佩戴」但实际合规的人数 / 总人数
```

目标 ≤ 10%。并记录误差来源分类：「远距离小目标」「逆光头部模糊」「帽檐颜色接近背景」……

> 误差来源分析比误报率数字本身更值钱。它证明你知道模型在哪里不行。

### 8.3 漏报率怎么测

用验证集里的**真实违规样本**测：

```
漏报率 = 实际违规但未被判出的人数 / 实际违规人数
```

安全场景漏报后果更严重，应主动在 PPT 里说明这个数。

### 8.4 三道无效性保护（降低误报）

模型不可能永远对，所以设计上不让单帧低质量检测直接变成误报：

| 保护 | 规则 | 防什么 |
|---|---|---|
| 置信度三档 | ≥0.30 定论 / [0.20,0.30) 转人工 / <0.20 丢弃 | 低置信度直接下结论 |
| 时序聚合 | 连续 3 帧判定一致才定论 | 单帧抖动、偶发遮挡 |
| 小目标拦截 | 人员框 < 8000 px² → 「无法判定」 | 远处模糊目标被误判违规 |

**答辩时说这三条，比说「我们模型很准」有效得多。**

## 十、降级方案

万一模型训不出来（11/03 晚 mAP 仍 < 0.5）：

1. **降级到单类**：只做 `helmet`，砍掉 vest / goggles
2. **用预训练模型直接推理**：公开的安全帽预训练权重，不做微调
3. **规则引擎不变**：整条链路照样能演示，只是指标不同

> 这是解耦架构的价值：模型降级不影响作品完整性。
