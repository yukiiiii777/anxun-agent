# 09 · 备选方案

> 三个方案都做过完整论证。选安巡，不是因为另外两个不好，是因为**时间和风险结构**决定了只能选一个。

## 一、三方对比

| 维度 | **安巡**（PPE 巡检） | 守净（院感防控） | 衡温（暖通选型） |
|---|---|---|---|
| 领域 | 制造 | 医疗 | 制造 |
| 一句话 | 摄像头 → 工单 | 摄像头 → 依从率曲线 | 参数 → 选型方案 |
| 视觉依赖 | 中（PPE 检测） | 中（姿态估计） | **零** |
| 演示观感 | **★★★★★ 有画面** | ★★★★ 有画面 | ★★ 纯对话 |
| 技术风险 | **低** | 中 | 低 |
| 数据可得性 | **高（公开集充足）** | **低（医疗数据敏感）** | 中 |
| 差异化 | 定级有据 + 闭环 | 消除霍桑效应 | 计算与语言分离 |
| 综合分 | **8.0** | 7.8 | 7.8 |

**选安巡的核心理由**：它是唯一一个「评委看 30 秒就明白你在干什么」的方案。

## 二、守净 Agent（医疗 · 院感防控）

### 2.1 想法

用视觉自动巡查院感防控的三件事：

- 手卫生依从性（洗手时机与动作）
- 防护穿戴（口罩、手套、隔离衣）
- 医废分类

### 2.2 核心创新点

**消除直接观察法的霍桑效应。**

院感科现在靠「直接观察法」抽查手卫生依从率——但人一被看着就会认真洗手，测出来的依从率是虚高的。这是院感领域的公认方法学缺陷。

用摄像头自动观察，不惊动人，测出来的才是真实依从率。

第二个创新点是**SPC 过程预警**：不是等依从率掉到某个阈值才告警，而是用统计过程控制看趋势拐点，在恶化之前预警。

### 2.3 技术路线（四层，不需要从零训练高精度检测器）

```
① 开源姿态估计（MediaPipe / RTMPose）
      ↓ 关键点
② 关键点几何 + 时序规则（手有没有到洗手池、停留多久）
      ↓
③ 多帧聚合（连续 N 帧一致才判定）
      ↓
④ 可选：小规模微调
```

> 这条路线当时是专门为「不从头训模型也能做」设计的，技术风险其实不高。

### 2.4 为什么没选

| 原因 | 说明 |
|---|---|
| **数据最难拿** | 医院场景影像涉及患者隐私，自采基本不可能；公开的院感行为数据集极少 |
| **演示最尴尬** | 没有真实画面可放，只能用示意图或公开视频，观感打折 |
| **验证最难** | 手卫生动作的「正确性」判断是语义问题，和火灾检测一样难 |
| **专业门槛** | 院感是专业领域，答辩时评委若懂行，容易问到答不上来 |

**结论**：方案本身成立，但数据这一关过不去。留着，如果以后有医院合作资源可以重启。

## 三、衡温 Agent（制造 · 暖通选型与运维）

### 3.1 想法

面向暖通（HVAC）工程的设备选型与运维问答 Agent。**零视觉依赖，纯知识 + 计算。**

### 3.2 真实参数资产

这个方案有个别人没有的优势：**手上有真实的工程图纸与参数**。

**39XT1822 卧式组合空调箱**

| 项 | 值 |
|---|---|
| 外形尺寸 | 3200 × 2304 × 2004 mm |
| 功能段 | 5 段 |
| 管口 | DN80 |
| 风量 | 28000 m³/h |

**30XAV0532A 风冷 V 型螺杆冷水机组**

| 项 | 值 |
|---|---|
| 外形尺寸 | 4798 × 2253 × 2297 mm |
| 制冷量 | 528 kW |
| 管口 | DN125 |
| 风机 | 8 台 |

### 3.3 最强技术点：计算与语言分离

> **LLM 不做算术。**

选型要算冷负荷、风量匹配、管径校核。这些交给 Python 算，LLM 只负责理解需求、组织表达、解释结果。

这和安巡的「风险矩阵不让模型算」是同一个设计哲学——**确定性的事交给确定性代码**。

### 3.4 为什么没选

| 原因 | 说明 |
|---|---|
| **没有画面** | 纯对话界面，6 分钟视频很难做出层次 |
| **痛点不够尖锐** | 选型算错是效率问题，不是安全问题；评委共情度低 |
| **容易被当成 RAG demo** | 说实话，这类作品很多，差异化难讲清 |
| **评分维度吃亏** | 官方六章里有「数据收集与处理」「分析过程」，纯对话方案在这两章没什么可写的 |

**结论**：技术最干净，但**演示最弱**。大赛是通讯评审看视频，这一条就出局了。

## 四、一个重要的判断失误（记录在案）

调研过程中曾出现一次误判：

> 因为「不做火灾模型了、准确度有问题」，一度推断为「不具备视觉能力」，据此把工厂巡检方案整个废弃，并把医疗方案的技术风险打高分。

**这是错的。** 实际情况是：

> 「不是不用视觉模型了，我们可以训练模型，只是之前的火灾的比赛完之后我就没有优化过了。」

修正后：

- 医疗方案的技术风险从 5 分下调，综合分从 6.8 修正为 7.8
- 工厂巡检方案恢复，只换感知任务（火灾 → PPE）

### 这次失误的教训

**场景对不对，和感知任务选哪个，是两件独立的事。**

工厂巡检这个场景一直是对的——它天生是完整闭环、有画面、法规刚性。错的是「用火灾检测来做这个场景」这个技术选择。

不该因为一个技术选择失败，就把整个场景扔掉。

> 这个判断后来变成了第 12 页 PPT 的核心论点：**「场景是对的，感知任务选错了。」**

## 五、三个方案共用的设计哲学

不管选哪个，下面三条是一样的：

1. **确定性的事交给确定性代码** —— 风险矩阵、冷负荷计算，都不让 LLM 算
2. **每条结论要有出处** —— 法规条款、工程参数、检测置信度
3. **主动说局限** —— 装完美的作品在答辩现场一戳就破

这三条是这三个方案真正的共同底子。
