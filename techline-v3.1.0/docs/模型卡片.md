# 模型卡片 · 安巡 Agent 技术线 v3.1.0

> 技术线交付物之一是「**能跑的模型**」。本卡片说明权重是什么、从哪来、怎么验证它能跑。
> 全部数字由脚本核对，重跑 `python src/anxun/verify_all.py` 即可复现。

## 一、模型的构成

**v3.1.0 是单模型链路：一份权重、一次前向、出全部框。**

| 权重 | 用途 | 结构 | 输出类别 | 体积 | 来源 | 自训 |
|---|---|---|---|:---:|---|---|
| `models/best.pt` | **主模型**：人体 + 安全帽 + 裸头 + 反光背心 | **YOLOv8s**（11.14 M 参数） | `helmet / no-helmet / no-vest / person / vest` | 21.48 MB | **本项目自训**：`ppe_full` 2451 训练 / 272 验证，80 轮，best ep62 | ✅ |
| `models/yolov8n.pt` | 可选兜底：仅当 PPE 权重**没有** `person` 类时才会被加载 | YOLOv8n（COCO 80 类） | `person` | 6.24 MB | `kadirnar/yolov8n-v8.0`（HF 镜像） | ❌ |

**演进**：v2.x 是三模型串联（COCO 人体 + 第三方安全帽 + 自训背心）→ v3.0.0 是双模型
（自训五类 + COCO 人体兜底）→ **v3.1.0 单模型**。

单模型不是省事，是更准也更快：同一次前向拿到的 person 与装备框出自同一套坐标，
头部区域推算不会错位；实测 person AP **0.8463**，高于外挂 yolov8n 的 0.7971；
单帧 22.9 → **15.0 ms**。`vest.pt` 已删除——五类权重自带 vest / no-vest，
再挂一个独立背心模型会把同一件背心检出两遍。

`build_detector()` 的规则：**PPE 权重自带 `person` 时优先用自己的**（v3.1.0 默认走这条）；
显式要外部人体模型时传 `prefer_own_person=False`。torch 与 ONNX 两个后端走同一套规则，
否则同一份 `metrics_*.json` 会对不上。

**对外表述的边界**：可以说「自训五类 PPE 权重」，但必须同时说清三点——
① 训练数据是公开集 `Chapian/ppev3`（Roboflow `ppe-detection-9p0pu` v3，CC BY 4.0），**无自采**；
② YOLOv8s 架构来自 Ultralytics；
③ 指标测在同源 100 张测试集上，跨域泛化未验证（见第五节）。

> **为什么不是 YOLO11：** 权重是 YOLOv8 结构，`.pt` 不跨版本兼容，换架构等于丢权重
> 重新训，并连带重扫判定阈值、重验 ONNX 一致性；实测收益只有 6% 耗时（同规模 CPU
> 41.4 vs 44.2 ms）。完整账见 README 4.2。

## 三、为什么要 .pt 和 .onnx 两份

| | `.pt` | `.onnx` |
|---|---|---|
| 运行时依赖 | torch（本机 1.99 GB） | onnxruntime ≈ 80 MB |
| 用途 | 训练、评测、重新导出 | **部署运行**（任意电脑） |
| 单帧耗时 | **15.0 ms**（GPU，p95 17.9） | **36.5 ms**（CPU，p95 39.1） |
| 输出一致性 | — | 已验证：标签完全一致，置信度最大偏差 0.001 |

> 单帧耗时的唯一口径：`evaluate_real.py` 在 100 张测试集上的均值（含前后处理）。
> **22 ms / 46 ms / 53.5 ms 都是 v2.x–v3.0.0 的旧数，已作废**；
> 当前 torch-GPU 15.0 ms、ONNX-CPU 36.5 ms，见 `docs/技术口径.md` 3.2。

`.onnx` 是从 `.pt` 导出的快照。**改了 `.pt` 必须重导 `.onnx`**——本轮就踩过这个坑：
`vest.pt` 更新后 `vest.onnx` 还是上一代，验收脚本一跑就抓出来了（torch 0.816 vs onnx 0.716）。
这种错误不会报错，只会让"可移植版"悄悄跑错模型。

## 四、怎么拿到权重

**权重随仓库分发** —— `models/` 共 82.6 MB，单文件最大 42.68 MB（GitHub 硬限制 100 MB）。
克隆下来就有，不用再到处找。拿到先核一次指纹，确认是同一份：

```bash
python -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('models/best.pt').read_bytes()).hexdigest())"
```

只想要部署用的那一份：`models/onnx/best.onnx` + `models/onnx/manifest.json` 就够，
配套 `requirements-cpu.txt`（约 80 MB，不装 torch）。

**改了 `.pt` 必须重导 `.onnx`**：

```bash
python src/anxun/export_onnx.py
```

**重训五类权重**（数据从公开源重建，2451 训练 / 272 验证）：

```bash
python tools/build_ppe_full.py                              # 9 类重映射为 5 类，剔除评测集重叠图
python src/anxun/finetune.py --data datasets/ppe_full/data.yaml \
    --init models/yolov8s.pt --name ppe_full_s --epochs 80 --batch 16 --imgsz 640
python src/anxun/export_onnx.py                             # 重新导出 .onnx
python src/anxun/verify_all.py                              # 验收
```

> `models/yolov8s.pt` 是训练起点，**不入库**（`.gitignore` 已排除），需要时 `yolo` 会自动下载。

集齐后跑一次 `python src/anxun/verify_all.py`：
仓库自带权重、评测集与演示素材时是 **60 项：PASS 57 · FAIL 0 · SKIP 3**（跳过的 3 项是 helmet_p2 训练集 2 项 + 1080p 复验素材 1 项）；
把 `tools/fetch_helmet_p2.py`、`tools/make_1080_stream.py` 跑一遍补齐，则是 **60 项全 PASS**。

## 五、已知限制（不藏）

| 项 | 实测 | 说明 |
|---|---|---|
| helmet AP@0.5 | **0.8845** | v3.1.0 自训权重（v3.0.0 是 0.7545，v2.2.0 第三方是 0.5645） |
| person AP@0.5 | **0.8463** | 单模型自带 person，高于外挂 COCO 的 0.7971 |
| 业务指标 | **0.8654 / 6.12% / 4.35% / 15.0 ms** | 四项全部达标（v3.0.0 时是 0.7758 / 10.20% / 16.13% / 19.5 ms） |
| 域匹配 | 偏弱 | 训练/测试数据均为境外工地照片，与国内车间存在域差 |
| 小目标 | 有限 | 安全帽在 640 输入下仅 20–30 px，远距离人员会被判「无法判定」 |
| 跨域泛化 | **很弱，已验证** | 706 张真跨源集上 helmet AP **0.2345**、nohelmet 0/764。同源零重叠（35 张）是 0.615，两者别混 |

**结论**：v3.1.0 把检测层推到 helmet AP 0.8845，四个业务指标 **全部达标**（0.8654 / 6.12% / 4.35% / 15.0 ms）。剩下的短板只有一个：4 例漏报里 2 例是软布帽被当成安全帽，要治它只能补负样本重训——数据集里没有。
