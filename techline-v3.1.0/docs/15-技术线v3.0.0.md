## 一、一句话结论

**模型换成自己训的了，检测层全面变强；业务指标是一笔明码标价的交换——漏报降 1 个点，误报涨 4 个点。**

| 指标 | v2.2.0 | **v3.0.0** | 变化 |
|---|---:|---:|---|
| mAP@0.5（person+helmet 均值） | 0.6808 | **0.7758** | +9.5 |
| helmet 单类 AP | 0.5645 | **0.7545** | **+19.0** |
| 误报率 | 6.12% | 10.20% | **+4.08** |
| 漏报率 | 17.20% | **16.13%** | **−1.07** |
| vest mAP@0.5 | 0.4524 | **0.5214** | +6.9 |
| vest 误报 / 漏报 | 27.27% / 11.35% | **25.00% / 8.65%** | 双改善 |
| 单帧耗时（GPU） | 21.82 ms | **18.09 ms** | −3.7 ms |
| 权重体积 | 105 MB（3 个 .pt + 3 个 .onnx） | **31 MB**（2 个 .pt + 2 个 .onnx） | −70% |

**误报涨的 4 个点必须一起报。** 只报「漏报降了、AP 涨了」是选择性陈述。

## 二、为什么误报会涨——以及为什么还是换了

### 2.1 换掉的是「谁在判」

v2.2.0 的 helmet 权重是第三方的 `keremberke/yolov8s-hard-hat-detection`，它只认两类
（Hardhat / NO-Hardhat），在自有测试集上 AP 0.5645，但**业务误报只有 6.12%**——
因为它和现有判定链（IoU + 包含度 + 头部区域 0.30/0.44）是在同一批数据上一起调出来的。

v3.0.0 换成自训的五类权重（含 person），检测层三项指标全面领先：

| | v2.2.0 第三方权重 | v3.0.0 自训权重 |
|---|---:|---:|
| helmet 精确率 @conf0.25 | 0.482 | **0.637** |
| helmet 召回率 @conf0.25 | 0.836 | 0.829 |
| 假框数（FP） | 131 | **69** |

**假框少了一半，召回没丢。** 这是换模型的底气。

### 2.2 换了模型就必须换判据

新的头盔框贴得更紧：站姿中景的人 `person` 框宽约 70 px，头部区域按 0.44 收窄只剩 31 px，
而头盔框本身宽 29 px——**横向偏 8 px，包含度就从 1.0 掉到 0.5，明明戴了也判「没戴」**。

实测（旧集 100 张，IoU/包含度判据）：

| 区域参数 | 误报 | 漏报 |
|---|---:|---:|
| 0.30 / 0.44（原口径） | 22.92% | 30.38% |
| 0.30 / 0.80 | 3.12% | 39.24% |
| 0.55 / 0.44 | 38.54% | 24.05% |

整条曲线都在 v2.2.0 的 (6.12%, 17.20%) 右下方——**几何判据对这套权重无解**。

换成「框中心落在区域内即达标」后：

| conf | 旧集 误报/漏报 | 新集 误报/漏报 |
|---|---|---|
| 0.45 | 7.14 / 23.66 | 4.17 / 12.50 |
| 0.55 | 8.16 / 19.35 | 6.25 / 12.50 |
| 0.58 | 9.18 / 18.28 | 7.64 / 12.50 |
| **0.59** | **10.20 / 16.13** | **8.33 / 12.50** |
| 0.65 | 16.33 / 15.05 | 15.28 / 12.50 |

取 **0.59**：漏报 16.13% 优于 v2.2.0 的 17.20%。再往上一档（0.65）漏报能到 15.05%，
但误报 16.33% 已经不像话了；往下（0.55）误报 8.16% 更漂亮，漏报却退回 19.35%。
**这一档是「漏报优先」的选择，不是最优解。**

## 三、改了什么（四条，都在 `src/anxun/rules_engine.py`）

| 变更 | 作用 | 默认行为变了吗 |
|---|---|---|
| `MATCH_MODE` + `equip.match_mode` | 装备框可按「IoU/包含度」或「中心点」判达标，逐装备可配 | 否，默认仍是 `iou` |
| `CONFLICT_POLICY` | 正反证据同框冲突时，可选转「待复核」或直接判「未佩戴」 | 否，默认仍是 `review` |
| `PERSON_CONF_FINAL` | 人员框定论阈值与装备框**解耦** | 否，未配则跟随 `conf_final` |
| `DualDetector.drop_equip_person` | 装备模型自带的 person 类不再合并进来 | 否，老的两类权重本来就没有 person |

四条都是「新口径才启用」，`measured` 口径下的行为逐位不变——已用老权重复跑验证：
**0.6808 / 0.5645 / 6.12% / 17.20% / vest 0.4524 / 27.27% / 11.35%，与 v2.2.0 交付逐位一致。**

### 3.1 踩到的两个坑（都写进注释了）

**坑一：中心点判据把低置信框也算「找到」。**
0.2~0.4 的框在旧判据下不达标、被忽略（正确判未佩戴），在新判据下却被当成「找到了」，
触发「丢弃 / 待复核」——而这两种状态在 `business_rates` 里**都算漏报**。实测漏报从 15% 顶到 49%。
修法：中心点判据只认达到 `CONF_FINAL` 的框。

**坑二：`CONF_FINAL` 被人员和装备共用。**
把装备阈值抬到 0.55 后，大量置信度 0.3~0.5 的 COCO 人体框落入「待复核」，漏报再涨 16 个点。
修法：拆出 `PERSON_CONF_FINAL`，v3 口径下固定 0.30。

### 3.2 顺手修了一个真值口径的 bug（影响所有历史对比）

`evaluate_real.truth_of` 判断「标注里这个人头上有没有帽子框」时，用的是
`HEAD_REGION_RATIO` 的**导入快照**——切换 `profile` 不会更新它。

后果：v3 默认口径 0.26/0.70 会连带改变真值推导的区域，可判人次从 212 变成 266，
两套数字根本不可比。这也违反了项目自己的原则「真值从标注来，判定从引擎来」。

修法：钉死 `TRUTH_HEAD_REGION = 0.30 / TRUTH_HEAD_WIDTH = 0.44`（即 v2.2.0 measured 的值），
真值推导从此不跟随判定口径。修复后 v2.2.0 的历史数字逐位不变，v3 的分母也可比。

## 四、跨源验证（新数据域）

同一套权重在 `datasets/ppe1206/test`（90 张，与旧集零重叠）上：

| 指标 | v2.2.0 老链路 | **v3.0.0** |
|---|---:|---:|

| 漏报率 | 12.50% | 12.50% |

新域上误报降 16 个点，这是 v3 最值钱的地方：**换域不崩**。

> ⚠️ **2026-11-04 更正：这句话已收回。** 该「跨源」集 `ppe1206/test` 与 v3.0.0 的训练集同源，目标域的 train/valid 参与过微调，所以它只能算同源留出。用完全不含该源的 `ppe_full` 重训后（v3.1.0），706 张真跨源集上 helmet AP 只有 **0.2345**。详见 `docs/16` 与 README 5.11。

# 附录 A · 调优全记录（2026-11-02 晚）

主口径数字定稿后又扫了一轮，目标是看「误报能不能压回 10% 以内、同时漏报不反弹」。
结论：**参数层面已到顶，模型层面 n 是最优，剩下的瓶颈不在调参。**

## A.1 扫过的四类参数

| 实验 | 网格 | 结果 |
|---|---|---|
| conf × 人员面积下限 | conf 0.52–0.60 × `min_person_area` 8000/5000 | **面积下限完全无效**，两档结果逐位相同；说明没有目标卡在 5000–8000 px² 之间 |
| conf 临界区细扫 | 0.575–0.600，步长 0.0025 | **离散台阶**：0.5775 及以下 8.16/18.28；0.5800 为 9.18/18.28；**0.5825 起跳到 10.20/16.13**，之后到 0.600 不再变 |
| vest 几何参数 | iou 0.05–0.20 × contain 0.30–0.60 × max_ratio 6–10 | **完全无反应**，误报恒为 25.00%、漏报 8.65–9.73% |
| vest 置信度 | conf_final 0.25–0.5825 | **完全无反应**，25.00/8.65 恒定 |

conf 的台阶说明：中间没有连续可调空间。0.5825 是「漏报跳到 16.13」的最小阈值，
取 0.59 与取 0.5825 结果完全一致（0.59 留了 0.0075 的余量，防浮点抖动）。

## A.2 模型对比：n 胜，s 负收益

同一混编集分别训 YOLOv8n 与 YOLOv8s，同口径评测：

| | 验证集 mAP@0.5 | 旧集 helmet AP | 旧集 误报/漏报 | vest AP | vest 误报/漏报 |
|---|---:|---:|---|---:|---|
| **混编 n（采用）** | 0.829 | 0.7545 | **10.20 / 16.13** | **0.5214** | 25.00 / **8.65** |
| 混编 s（放弃） | **0.891** | **0.7658** | 16.33 / 16.13 | 0.5193 | 25.00 / 11.89 |

s 的验证集 mAP 高 6 点、helmet 单类 AP 也更高，但**业务指标全面落后**：
同漏报下误报高 6 个点，背心漏报差 3.2 个点。

原因：旧集目标更小（框面积中位数 0.0047），s 的额外容量主要变成了假阳性。
**验证集 mAP 与业务指标在这批数据上不是正相关**——这条要写进模型选型结论。

## A.3 瓶颈一：vest 是「看不见」，不是「判错了」

把 11 例「穿了却判没穿」逐例拆开：

| 成因 | 例数 |
|---|---:|
| 整图没有任何 vest 框 | **10** |
| 有框但置信度不达标 | 0 |
| 有高置信框但几何不匹配 | 0 |

10/11 是模型**完全没检出背心**，所以 A.1 里几何与置信度两组参数才会毫无反应——
问题在上游。**加数据才是解，调参不是。**

## A.4 瓶颈二：helmet 漏报里混着标注噪声

15 个漏报里，10 例是「头顶有个高置信头盔框、但标注是 no-helmet」。
这些框的置信度高度集中：

```
0.67  0.67  0.67  0.67  0.68  0.68  0.73  0.74  0.77  0.80
```

中位数 0.68，若要靠阈值滤掉它们需要 conf ≥ 0.81（会同时滤掉大量真框）。**阈值不可行。**

逐例裁剪人工核查（图见 `docs/figs/annot_conflict_cases.png`）：

| 抽检样本 | 图中所见 | 判定 |
|---|---|---|
| case00 | 工人戴绿色安全帽 | **标注错误** |
| case02 | 戴红色帽子，是否为安全帽存疑 | 存疑 |
| case05 | 三人戴遮阳帽 / 布帽 | **模型误判** |
| case07 | 前景工人戴黄色安全帽 | **标注错误** |

另外全图目视可见 case08 一排工人戴绿色安全帽（也很可能是标注错）。

**抽检 4 例中 2 例明确是标注错误、1 例明确是模型误判、1 例存疑。**
所以不能说「漏报全是标注问题」——但也不能说「16.13% 全是模型问题」。

这条对答辩有用：被问到漏报时，可以说「15 个漏报里 10 个是模型与标注冲突，
抽检的 4 个里有 2 个确认是标注写错了」，但**必须同时说另外 1 个确实是模型判错**。

## A.5 剩余空间（按性价比）

| 措施 | 预期 | 成本 |
|---|---|---|
| 人工复核那 10 例标注 | 若确认 5–7 例为标注错，漏报可降到 11–13% | 半天 |
| 补 vest 训练数据 | 唯一能治「检不出」的办法 | 取决于能否找到带 vest 标注的公开集 |
| 继续调阈值 | **无收益**，A.1 已证明是纯权衡曲线 | — |
| 换更大模型 | **负收益**，A.2 已证明 | — |

> 一句话：**这一版的瓶颈已经不是「调得好不好」，是「数据够不够」。**

## B.2 这次复核改变了什么

**原来的判断（错）**：漏报主要是标注噪声，修一修能降到 11–13%。
**实际**：模型把「草帽 / 渔夫帽 / 软布帽 / 手里拿着的安全帽」都判成了「戴在头上」。

r09 那例最能说明问题：工人背对镜头、头顶什么都没有，却被判「已佩戴」。

> **一次错误归因的记录**：起初我判断是「模型把右手拎着的白色安全帽当成了戴在头上」，
> 于是实现了「框上沿必须贴近头顶」的约束去挡它——扫了 0.08~0.30 五档，指标一格没动，
> 判定也没变。**说明误检框本来就在头顶位置**：模型把深色的**后脑勺**当成了深色头盔，
> 画面里那顶白帽子只是干扰项。这类错误几何约束管不了。

## B.3 两条几何路都试过，都不行

**第一条：贴头约束**（要求装备框上沿贴近头顶，挡住「帽子在手里」）。
实现为 `HEAD_TOP_TOL`，扫 0.08~0.30 五档：**指标与判定全无变化**——
因为误检框本就在头顶，不在手里。代码保留但默认关闭，注释里写明了实测无效。

**第二条：收紧中心点判据的纵向窗口**，让「偏下的帽子框」不算数：

| ratio / width | 误报 | 漏报 | 说明 |
|---|---|---|---|
| 0.26 / 0.70（当前） | 10.20% | 16.13% | 基线 |
| 0.22 / 0.70 | 10.20% | 16.13% | 无变化 |
| 0.18 / 0.70 | 11.22% | 16.13% | 白涨误报 |
| 0.15 / 0.70 | 12.24% | **15.05%** | 救回 1 例，赔 2 例误报 |
| 0.15 / 0.55 | 13.27% | 15.05% | 更差 |

收紧到 0.15 能救回 1 例漏报，但误报涨 2 个点——**不划算，不采用。**

根子上的原因：训练集里没有「普通帽子」这个负类，模型只学过「头盔 / 裸头」两种，
遇到草帽只能往最近的一类靠。**这需要数据，调参无解。**

## B.4 修正标注后的参考指标

把 r00、r07 两例确认的标注错误改对（no-helmet → helmet），其余不动：

| | 主口径（原始标注） | 参考口径（修正 2 例） |
|---|---:|---:|
| 误报率 | 10.20% | 10.20%（不变） |
| 漏报率 | 16.13%（15/93） | **13.98%（13/93）** |

## B.5 复核的净收获

1. **避免了答辩时说错话**：如果按 A.4 的推测去说「漏报大半是标注问题」，
   被评委抽到 r09 那张（手拿帽子）会很难看。
2. **排除了一条看似合理的修法**：贴头约束无效，说明这批错误不是「位置偏了」，
   是「模型把后脑勺认成了头盔」。省下了 v3.1 在这条路上的时间。
3. **明确了下一步要的是数据不是参数**：需要「戴普通帽子」的负样本，
   或者「头盔必须与头部中心距离足够近」的第二重约束。
