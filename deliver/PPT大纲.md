## 逐页大纲

### 封面 · 01
**安巡 Agent｜厂区安全巡检多智能体系统**
- 副题：把摄像头画面变成**可执行的整改工单**
- 通用赛道 · 制造领域 · 2026 年 11 月（不出现学校、姓名、指导教师）

### 第 1 章 · 作品背景与说明

**02 别人做告警，我们做工单**
- 一句话定位：告警是一条通知，工单是一个责任
- 解决什么：「看到未戴安全帽」之后，没人负责把它变成限期整改、可签署、可追责的通知单
- 三条交付线：技术线（权重/评测/ONNX 服务）· 系统线（规则引擎/研判台/Word 工单）· 材料线（PPT/视频/提交包）
- 参考来源单列：数据集与许可、安全生产法条号、GB 2811-2019 / GB 39800.1-2020、YOLOv8s / ONNX Runtime / FastAPI；配《国务院公报》封面缩略图

**03 法规是刚性的，执行是虚化的**
- 法规侧：《安全生产法》第四十五条要求提供并监督佩戴；两项国标对安全帽与配备规范有要求；企业要留痕（谁检查、发现什么、多久整改、谁验收）
- 执行侧：一名安全员管多个车间，人工巡查每班仅 2 次 × 15 分钟；195 条逐帧告警 / 13 个真实事件 / 30 分钟每班
- 结论：不是工人不怕，是没人盯得住；不是没有摄像头，是没人把画面变成一件要办的事
- 配两张官方文件真实截图：国发〔2025〕11 号《关于深入实施「人工智能+」行动的意见》原文页、主席令第八十八号（《安全生产法》修改决定）

### 第 2 章 · 数据收集与处理

**04 数据来源一 · 主训练集：2,451 张训练图像，全部可追溯**
- Chapian/ppev3（CC BY 4.0），272 张验证，17,610 个标注框，剔除 165 张重名防泄漏
- 9 类重映射为 5 类：person / helmet / no-helmet / vest / no-vest；一次前向出全部框，不外挂 COCO 人体模型
- 自采 0 张；goggles 等类别不参与判定、只留接口；对外只说「自训五类 PPE 权重」

**05 数据来源二 · 独立评测集：100 张，全程不参与训练与选轮次**
- 单独下载、单独建索引，不进训练目录；四个对外指标的唯一报数出口
- 真值由标注框推导（Hardhat 落头部记合规、只有 NO-Hardhat 记违规、两者都无则跳过）
- 诚实边界：判定结论由规则引擎给出，不由模型自由发挥

**06 知识库构建：四层知识库，每条结论可追到条号**
- 法规层 / 标准层 / 操作层 / 经验层；原文与摘要严格区分
- 条文库怎么被调用、为什么要做白名单；查不到就写「未检索到」

**07 数据预处理流程：每种增强都对应一个现场问题**
- 逆光 / 弱光 / 遮挡 / 监控距离 / 安装倾斜
- 不是「做了数据增强」，而是增强与失效模式一一对应

### 第 3 章 · 分析过程

**08 分析方法选择：等级只由本次人数决定，不由模型拍脑袋**
- 四版风险矩阵的推翻过程：L 取区域近 30 天违规次数 → 同一张图换区域等级就变；S 取作业类型 → 回答「场景多危险」而非「多久要处理」
- v1.4 定档：≥3 人 A 级 2 小时内 / 1–2 人 B 级 24 小时内 / 仅待复核或无法判定 C 级 7 天内核实 / 全合规不出单
- 为什么要拆成多个 Agent：职责分离，等级、时限、工单号交给代码

**09 分析流程思维导图：一帧画面 → 一张工单**
- ① 四态判定（已佩戴 / 未佩戴 / 待复核 / 无法判定）② 三道无效性保护（置信度三档 / 连续 3 帧 / 小目标拦截）③ 时序聚合 195→13 ④ v1.4 分档 ⑤ 等级与时限 ⑥ 法规映射 ⑦ 工单生成 ⑧ 签署与复查
- 中心问题只有一个：这一帧，最后要谁、在多久之内、办成一件什么事

**10 系统架构：判定逻辑与检测模型解耦**
- 检测模型 → 规则引擎 → Agent 编排 → 整改通知单
- 五 Agent 职责、两个后端、一条原则（确定性的归代码，理解与表达归模型）

### 第 4 章 · 创新性与独特视角

**11 模型实测指标：四个数，一个说得清的口径**
- mAP@0.5 **0.8654**（目标 ≥0.85）· 误报 **6.12%**（6/98，目标 ≤10%）· 漏报 **4.35%**（4/92，目标 ≤5%）· 单帧 **15.0 ms GPU**（目标 ≤50 ms，ONNX-CPU 36.5 ms）
- 口径：100 张独立评测集 · rules_profile v3 · 中心点判据 · conf 0.65 · min_aspect 0.80
- 误差归因：判定覆盖 89.62%（190/212 人次），4 例漏报中 2 例是「无法判定」被正确保护
- 诚实边界：漏报 95% 区间 1.7%–10.7%、误报 2.8%–12.7%，上界越线 → **只能说点估计达标**

**12 为什么放弃火焰检测：场景是对的，感知任务是选的**
- 火焰检测属语义判断：蒸汽、夕照、红色工装、焊花都易误报，标注本身有分歧
- PPE 检测属存在性判断：漏报看得见、归因得到（小目标、遮挡、框没对齐）
- 上一轮准确率问题本质是任务级语义模糊，不是「没有视觉能力」

**13 创新点与跨学科视角：看得见 → 判得准 → 落得下**
- ① 感知闭环 ② 定级有据 ③ 可解释的克制（模型能说「我不确定」「待复核」）
- 安全工程 × 计算机视觉 × 管理学 PDCA

### 第 5 章 · 结果解释与建议

**14 结果解读：同一张图换区域，等级不变**
- 线上接口实测四场景（同一批 best.onnx）：二楼平台 1 人 B 24h / 装卸区 8 人 A 2h / 喷漆房 5 人 A 2h / 通道全合规不出单
- 结论：等级回答「多久处理」，不由台账和作业类型替你回答；「没有工单」也是一次完整研判

**15 价值量化：195 条告警，只留下 13 件该办的事**
- 34.8 秒单路视频、28 人次 → 195 条逐帧告警 → 连续 3 帧聚合后 13 个事件，**降噪 93.33%**
- 判定覆盖率 76.92%（10/13）、helmet 合规率 57.14%（4/7，待复核单列不进分母）
- 实测与推演分栏：16× 巡检覆盖来自排班假设，**不是实测**，不拿假设冒充结果

**16 问题与优化建议：六条局限**
- 自采 0 张 / 评测集仅 100 张 / 背心类明显更弱 / 类别覆盖不全 / 现场素材有限 / 离线依赖
- 逐条给出改进路径，明确结果适用边界

**17 风险识别与应对：隐私、误报信任、责任边界**
- 三道无效性保护；一条不越界的叙事红线：不宣称自动指派责任人，工单卡片责任人/复查人/验收项留空由现场手填

### 第 6 章 · 应用结果呈现

**18 应用对话界面：真实研判台，不是设计稿**
- 整屏真实交互截图：左侧真实提问 + 云端 Agent 实时回复（非预置回答），右侧四态统计、B 级 24 小时内、工单号、法规依据
- 上传真图片 → best.onnx 实算 → grade_risk 定级 → 导出 1 页 Word《安全隐患整改通知单》→ 工具轨迹可查
- 现场需联网（无离线降级），另备录屏

**19 成果展示：三组真实对话与 Agent 在线链接**
- 三张线上研判台实跑截图（2026-11-10，未做后期合成）：B 级 24h（1 人）/ A 级 2h（8 人）/ 不出单（全员已佩戴）
- 黑色气泡真实输入、白色气泡云端实时回复、蓝色小字工具调用轨迹；等级/时限/工单号不交给大模型
- 二维码与链接含完整 `?sharecode=OLOGYZUPHO`；C 档为规则补充，不冒充实测
- 逐字版见 `docs/12-Agent提示词示例.md`

**20 结尾与展望：把一次「看见」，变成一件办得完的事**
- ① 先把判定做稳 ② 再把闭环接通 ③ 最后扩到更多场景
