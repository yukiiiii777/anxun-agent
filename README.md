# 安巡 Agent

**厂区安全巡检多智能体系统** —— 把摄像头画面变成可执行的整改工单。

| 赛事 | 组别 | 领域 | 提交死线 |
|---|---|---|---|
| 第二届全国人工智能应用创新大赛<br>通用赛道 · 三级赛制 | 本科生组 | 制造 | **2026-11-10 24:00** |

---

## 一句话说清这个作品

> 别人做的是**告警**，我们做的是**工单**。
> 告警是一条通知，工单是一个责任。

摄像头识别出「有人没戴安全帽」，这是现有方案都能做到的事。但厂区安全管理的真实缺口不在识别，而在识别之后——

- 这条违规该谁处理？
- 多久之内必须整改完？
- 为什么是这个等级，不是别的等级？
- 整改完了谁来验收、怎么留痕？

安巡 Agent 做的是把「一个检测框」变成「一条带责任人、带时限、带法规依据、可验收的闭环工单」。

## 核心设计：判定逻辑与检测模型解耦

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  检测模型     │ ───> │   规则引擎    │ ───> │  Agent 编排   │
│  看得见       │      │   判得准      │      │   办得成      │
│  YOLO11      │      │  纯 Python    │      │  扣子工作流    │
└──────────────┘      └──────────────┘      └──────────────┘
  infer_api.py          rules_engine.py        提示词 + 知识库
```

这条边界是整个作品的技术底座。四条好处：

1. **模型没训好也能演示** —— 规则引擎跑模拟框就能出完整结果（`demo.py` 零依赖可跑）
2. **换模型不影响业务逻辑** —— YOLO 换 RT-DETR 只改 `infer_api.py`
3. **换平台不用重写** —— 扣子换 JoyCode 只改调用地址
4. **结果可复现** —— 同一输入永远同一输出，答辩敢让人当场重算

### 五 Agent 分工

| # | Agent | 职责 | 是否保留 |
|---|---|---|---|
| ① | 巡检规划 | 根据厂区区域与风险等级排巡检计划 | 可砍 |
| ② | 视觉感知 | 调检测模型，输出四态判定（已佩戴/未佩戴/无法判定/待复核） | **骨架** |
| ③ | 隐患研判 | 风险矩阵定级（R = L × S），给出法规依据 | **骨架** |
| ④ | 工单生成 | 生成带责任人、时限、整改建议的工单 | **骨架** |
| ⑤ | 合规问答 | 安全生产法规知识库问答 | 可砍 |

> 时间不够时的砍功能顺序：先砍 ⑤ → 再砍 ①。②③④ 是故事的骨架，缺了就不成立。

## 快速开始

### 不需要模型，5 分钟看完整链路

```bash
cd src/anxun
python demo.py
```

纯标准库，不装任何依赖。会输出：

- 控制台完整报告（四态判定、风险定级、工单）
- `result.json` —— 结构化结果，可直接喂给 Agent
- `report.html` —— 带画面标注的巡检报告，**可直接截图进 PPT**

演示跑出来的四个点，正好覆盖四态：

| 人员 | 情况 | 判定 | 说明 |
|---|---|---|---|
| P1 | 安全帽置信度 0.93，IoU 达标 | **已佩戴** | 正常放行 |
| P2 | 安全帽置信度 0.52 | **待复核** | 落在 [0.40, 0.60) 灰区，转人工 |
| P3 | 无安全帽 | **未佩戴** | 确认违规，进入定级 |
| P4 | 人员框面积 6000 px² | **无法判定** | 小于 8000 px² 门槛，直接拦截不报违规 |

同一个「未佩戴安全帽」违规，三个场景三个等级（以下为 `demo.py` 真实输出）：

| 区域 | 场景 | 30 天违规 → L | 违规类型×场景 → S | R = L×S | 等级 | 整改时限 |
|---|---|---|---|---|---|---|
| 3 号车间东侧通道 | 普通 | 4 次 → L=3 | helmet·普通 → S=3 | **9** | 🟠 橙色 | 1 天内 |
| 2 号车间高处作业平台 | 高处 | 7 次 → L=4 | helmet·高处 → S=4 | **16** | 🔴 红色 | 2 小时内 |
| 原料库装卸区 | 车辆 | 1 次 → L=1 | helmet·车辆 → S=3 | **3** | 🔵 蓝色 | 30 天内 |

这就是「同样一条告警，不是同一个责任」的实证。同样是没戴帽子，在高处作业平台是立即停工的红色风险，在原料库装卸区只是加强关注的蓝色。

### 训练自己的模型

```bash
cd src/anxun
pip install -r requirements.txt

# 小显存先跑通
python train_yolo.py --device 0 --imgsz 480 --batch 16 --model yolo11n.pt

# 双卡正式训练
python train_yolo.py --device 0,1 --batch 32 --model yolo11s.pt
```

详见 [`docs/04-数据与模型.md`](docs/04-数据与模型.md)。

### 启动推理服务

```bash
set MODEL_PATH=runs/ppe/weights/best.pt
uvicorn infer_api:app --host 0.0.0.0 --port 8000
```

接口：`POST /detect`（表单上传）、`POST /detect_b64`（base64，给扣子插件用）、`GET /health`。

## 关键指标

### 目标值（待实测后回填）

| 指标 | 目标 | 实测 | 说明 |
|---|---|---|---|
| mAP@0.5 | ≥ 0.85 | — | 四类：person / helmet / vest / goggles |
| 误报率 | ≤ 10% | — | 比 mAP 更该强调，工业场景误报会让人关掉告警 |
| 漏报率 | ≤ 5% | — | 安全场景漏报后果更重，必须主动披露 |
| 单帧耗时 | ≤ 50 ms | — | 满足实时巡检 |

### 误报率的测法

准备一批**不含违规**的负样本图（正常戴帽的工人、空场景、设备特写）：

```
误报率 = 被判为「未佩戴」但实际合规的人数 / 总人数
```

### 三道无效性保护

模型不可能永远对，所以设计上不让单帧低质量检测直接变成误报：

| 保护 | 规则 | 防什么 |
|---|---|---|
| 置信度三档 | ≥0.60 定论 / [0.40,0.60) 转人工 / <0.40 丢弃 | 低置信度直接下结论 |
| 时序聚合 | 连续 3 帧判定一致才定论 | 单帧抖动、偶发遮挡 |
| 小目标拦截 | 人员框 < 8000 px² → 「无法判定」 | 远处模糊目标被误判违规 |

## 已知局限

主动写进 PPT 第 16 页，不藏：

- 规则依赖人工阈值，不同厂区像素尺度差异大，`MIN_PERSON_AREA` 需按相机标定重设
- 只覆盖正面 / 侧面视角，完全背影或俯视场景未验证
- 未做跨镜头人员重识别，同一人换镜头会重复计数
- 手部细粒度动作（如手套穿脱）不在当前范围内
- **真实模型尚未训练，当前所有指标为空**
