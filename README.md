## 现在的产品长什么样（2026-11-10）

一个页面，三块内容：

| 区域 | 显示什么 | 数据来源 |
|---|---|---|
| 左：对话 | 问判定、问定级、问法规、要工单 | 云端模型 + 四个 function calling 工具 |
| 右上：实时研判 | 四态判定 / 处置等级 / 整改要求 / 工单号 | **best.onnx 实测 + 规则引擎**，不是模型生成的 |
| 右下：整改工单 | 工单号、等级、时限、整改要求，可导出 Word | 同上 |

几条已经定死的产品规则：

- **只有一个内置样例区域**，页头不再有场景切换按钮；想看自己的画面，上传一张现场照片即可，右栏会跟着换。
- **判定只覆盖两类装备**：安全帽、反光背心。安全带、手套、护目镜不在检测范围，也不会出现在结论里。
- **对话只走云端一条路**。连不上就显示「云端未连接 · 点此重试」，不退回预置回答——演示现场出现「演示模式」四个字，前面讲的实测全白搭。
- **工单只写能确认的事实**。受检区域、作业类型、责任人、复查人一律留空，打印后手填；不出现具体人名、厂区地名，也不写还没发生的「复查记录」。
- **导出的是标准 Word**（.docx，纯前端生成、不依赖任何库）：安全隐患整改通知单，含基本信息表、违规事实、整改要求、法规依据、签署栏。
- **聊天记录本地保存**（含工具调用轨迹），刷新不丢；同一会话里研判卡片只出现一次，追问不复读。

## 一句话说清这个作品

> 别人做的是**告警**，我们做的是**工单**。
> 告警是一条通知，工单是一个责任。

摄像头识别出「有人没戴安全帽」，这是现有方案都能做到的事。但厂区安全管理的真实缺口不在识别，而在识别之后——

- 这条违规该谁处理？
- 多久之内必须整改完？
- 为什么是这个等级，不是别的等级？
- 整改完了谁来验收、怎么留痕？

安巡 Agent 做的是把「一个检测框」变成「一条带责任人、带时限、带法规依据、可验收的闭环工单」。

## 核心设计：判定逻辑与检测模型解耦

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  检测模型     │ ───> │   规则引擎    │ ───> │  Agent 编排   │
│  看得见       │      │   判得准      │      │   办得成      │
│  YOLO11      │      │  纯 Python    │      │  扣子工作流    │
└──────────────┘      └──────────────┘      └──────────────┘
  infer_api.py          rules_engine.py        提示词 + 知识库
```

这条边界是整个作品的技术底座。四条好处：

1. **模型没训好也能演示** —— 规则引擎跑模拟框就能出完整结果（`demo.py` 零依赖可跑）
2. **换模型不影响业务逻辑** —— YOLO 换 RT-DETR 只改 `infer_api.py`
3. **换平台不用重写** —— 扣子换 JoyCode 只改调用地址
4. **结果可复现** —— 同一输入永远同一输出，答辩敢让人当场重算

### 五 Agent 分工

| # | Agent | 职责 | 是否保留 |
|---|---|---|---|
| ① | 巡检规划 | 根据厂区区域与风险等级排巡检计划 | 可砍 |
| ② | 视觉感知 | 调检测模型，输出四态判定（已佩戴/未佩戴/无法判定/待复核） | **骨架** |
| ③ | 隐患研判 | 按处置时限分 A/B/C 定级，给出法规依据 | **已实现** |
| ④ | 工单生成 | 生成工单并导出标准 Word（.docx） | **已实现** |
| ⑤ | 合规问答 | 安全生产法规知识库问答 | 可砍 |

> 时间不够时的砍功能顺序：先砍 ⑤ → 再砍 ①。②③④ 是故事的骨架，缺了就不成立。

## 快速开始

### 不需要模型，5 分钟看完整链路

```bash
cd src/anxun
python demo.py
```

纯标准库，不装任何依赖。会输出：

- 控制台完整报告（四态判定、风险定级、工单）
- `result.json` —— 结构化结果，可直接喂给 Agent
- `report.html` —— 带画面标注的巡检报告，**可直接截图进 PPT**

演示跑出来的四个点，正好覆盖四态：

| 人员 | 情况 | 判定 | 说明 |
|---|---|---|---|
| P1 | 安全帽置信度 0.93，IoU 达标 | **已佩戴** | 正常放行 |
| P2 | 安全帽置信度 0.25 | **待复核** | 落在 [0.20, 0.30) 灰区，转人工 |
| P3 | 无安全帽 | **未佩戴** | 确认违规，进入定级 |
| P4 | 人员框面积 6000 px² | **无法判定** | 小于 8000 px² 门槛，直接拦截不报违规 |

等级只回答一个问题：**这一单要不要马上处理、多久内必须处理完。** 按处理时限分三档：

| 本次判定 | 等级 | 处理时限 |
|---|---|---|
| 确认未佩戴 **≥3 人** | **A 级 · 立即处置** | 2 小时内 |
| 确认未佩戴 **1–2 人** | **B 级 · 当日处置** | 24 小时内 |
| 无确认违规，仅待复核 / 无法判定 | **C 级 · 限期核实** | 7 天内 |
| 全部已佩戴 | 不出单 | 放行 |

实测（同一批权重，线上接口输出）：

| 场景 | 本次判定 | 等级 |
|---|---|---|
| 二楼平台 | 1 人未穿反光背心 | **B 级**（24 小时内） |
| 装卸区 | 8 人未穿反光背心 | **A 级**（2 小时内） |
| 喷漆房 | 5 人未戴安全帽 | **A 级**（2 小时内） |
| 通道 | 全部已佩戴 | 不出单 |

> **为什么不看作业类型、不看区域历史**：v1.0–v1.3 用的是 `R = L × S` 矩阵，
> L 取区域历史次数、S 取作业类型。结果是同一张图换个区域登记等级就变，
> 1 人少穿背心判红色、7 人全缺 PPE 判蓝色，C 档还被安全帽单占满。
> v1.4 把「危险程度」和「处置紧急程度」拆开：前者留在作业类型里作背景，
> 后者只看人数与处理时限。颜色（红/橙/黄/蓝）同步取消，对外只说 A/B/C。
>
> 详见 [《安巡风险分级标准 v1.4》](docs/安巡风险分级标准.md) §2 / §3。

### 跑三个 Agent（本地，不需要扣子）

`demo.py` 把链路跑给你看，`run_agents.py` 把链路拆成三个能对话的 Agent：

```bash
cd src/anxun
python run_agents.py            # 三个区域样例，终端看 ②→③→④ 的交接
python run_agents.py --scene B  # 只看 B 区域样例
python run_agents.py --serve    # 本地网页 127.0.0.1:8611，可直接截图进 PPT
```

纯标准库、离线、同一输入同一输出。设计取舍见 [`src/anxun/agents/README.md`](src/anxun/agents/README.md)。

### 训练自己的模型

```bash
cd src/anxun
pip install -r requirements.txt

# 小显存先跑通
python train_yolo.py --device 0 --imgsz 480 --batch 16 --model yolo11n.pt

# 双卡正式训练
python train_yolo.py --device 0,1 --batch 32 --model yolo11s.pt
```

详见 [`docs/04-数据与模型.md`](docs/04-数据与模型.md)。

### 启动推理服务

```bash
set MODEL_PATH=runs/ppe/weights/best.pt
uvicorn infer_api:app --host 0.0.0.0 --port 8000
```

接口：`POST /detect`（表单上传）、`POST /detect_b64`（base64，给扣子插件用）、`GET /health`。

## 关键指标

### 目标值 vs 实测

| 指标 | 目标 | 实测 | 说明 |
|---|---|---|---|
| mAP@0.5 | ≥ 0.85 | **0.8654** | 两类：person 0.8463 / helmet 0.8845。✅ **达标**，超 0.015；比 v3.0.0 的 0.7758 高 0.09 |
| 误报率 | ≤ 10% | **6.12%** | ✅ **达标**，余 3.9 点。v3.0.0 时是 10.20%（破线 0.2 点），这一版换 s 权重 + 单模型链路后压回来了 |
| 漏报率 | ≤ 5% | **4.35%** | ✅ **达标**。4 例里 2 例软布帽判错、2 例目标过小转人工。注意 95% 区间 1.7–10.7%，**点估计达标 ≠ 稳定达标** |
| 单帧耗时 | ≤ 50 ms | **15.0 ms**（GPU） | ✅ 达标，3.3 倍余量。ONNX CPU 36.5 ms；口径见 `techline-v3.1.0/docs/技术口径.md` |

> 数字来源：`techline-v3.1.0/data/metrics_real.json`（100 张测试集，`evaluate_real.py` 可复现）。
> 误报 / 漏报默认是**「已检出人员」口径**，引用时必须带这句，否则等于把检测漏检藏进分母。

> ⚠️ **两套口径，别混**：本页数字是**评测口径**（`rules_profile: v3`，中心点判据，conf 0.65）。
> `demo.py` 与三个 Agent 用的是**演示口径**（`src/anxun/rules_engine.py`，conf 0.30/0.20 + IoU 判据），
> 阈值更宽、四态齐全，为的是把「待复核」这一档演出来。同一张图两边判定可能不同，这是刻意设计、
> 不是 bug——但**对外报数只能用评测口径**。两套的差异与理由见 `techline-v3.1.0/docs/技术口径.md`。

### 误报率的测法

准备一批**不含违规**的负样本图（正常戴帽的工人、空场景、设备特写）：

```
误报率 = 被判为「未佩戴」但实际合规的人数 / 总人数
```

### 三道无效性保护

模型不可能永远对，所以设计上不让单帧低质量检测直接变成误报：

| 保护 | 规则 | 防什么 |
|---|---|---|
| 置信度三档 | ≥0.30 定论 / [0.20,0.30) 转人工 / <0.20 丢弃 | 低置信度直接下结论 |
| 时序聚合 | 连续 3 帧判定一致才定论 | 单帧抖动、偶发遮挡 |
| 小目标拦截 | 人员框 < 8000 px² → 「无法判定」 | 远处模糊目标被误判违规 |

> 上表的 0.30 / 0.20 是**演示口径**（`src/anxun/rules_engine.py`，四态齐全）。
> 评测口径是 conf 0.65 / 复核 0.20，阈值更严，数字见上面的「关键指标」。

## 已知局限

主动写进 PPT 第 16 页，不藏：

- 规则依赖人工阈值，不同厂区像素尺度差异大，`MIN_PERSON_AREA` 需按相机标定重设
- 只覆盖正面 / 侧面视角，完全背影或俯视场景未验证
- 未做跨镜头人员重识别，同一人换镜头会重复计数
- 手部细粒度动作（如手套穿脱）不在当前范围内
- **v3.1.0 起模型是自训的**：五类权重（person / helmet / nohelmet / vest / novest）在 2451 张上训练
  （源数据集剔除评测集重叠后）；但训练数据全部来自公开集，**无自采**
- **评测集只有 100 张**，单例权重 1%；绝对数值不宜外推，横向比较配置差异可用
- **指标已全部达标**：mAP 0.8654（目标 0.85）、误报 6.12%（≤10%）、漏报 4.35%（≤5%）、
  单帧 15.0 ms（≤50 ms）。但**漏报的 95% 区间上界 10.7% 仍越线**，只能说点估计达标
- 护目镜（goggles）只留了接口，无数据无权重，当前不启用
- **跨源泛化弱**：在 706 张跨源实拍上，helmet 的 AP 只有 0.2345（同源评测是 0.8654）。
  同域强、换域弱，上线前必须做域适配——这条已从早期 README 的「换域不崩」撤回
- **内置样例只有 4 张图**，全部来自公开数据集（CC BY 4.0），不是本厂现场记录；
  页脚已如实标注。真实场景请用上传功能
- **等级口径 v1.4 只看本次判定与处理时限**，不累计历史：同一处反复违规不会自动升级，
  历史次数只作背景。要做趋势管理需要另接台账
