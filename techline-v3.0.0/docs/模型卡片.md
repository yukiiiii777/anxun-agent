# 模型卡片 · 安巡 Agent 技术线 v3.0.0

> 技术线交付物之一是「**能跑的模型**」。本卡片说明两个模型各是什么、从哪来、怎么验证它能跑。
> 全部数字由脚本核对，重跑 `python src/anxun/verify_all.py` 即可复现。

## 一、两个模型

| 权重 | 用途 | 结构 | 输出类别 | 体积 | 来源 | 自训 |
|---|---|---|---|---|:---:|
| `models/yolov8n.pt` | 人体检测 | YOLOv8n（COCO 80 类） | `person` | 6.55 MB | `kadirnar/yolov8n-v8.0`（HF 镜像） | ❌ |
| `models/best.pt` | 安全帽 + 反光背心 | **YOLOv8n 五类**（`helmet / no-helmet / no-vest / person / vest`） | 四类装备证据 | 6.25 MB | **本项目自训**：混编 1097 张（ppe1206 997 + 旧集 100），80 轮 | ✅ |

**v3.0.0 起，装备模型是自训的。** `vest.pt` 已删除——五类权重自带 vest / no-vest，
再挂一个独立背心模型会把同一件背心检出两遍。对外可以说「自训五类 PPE 权重」，
但要说清楚人体仍用 COCO 预训练权重（person 类只作定位，不作判定）。

**对外表述的边界**：可以说「自训五类 PPE 权重」，但必须同时说清三点——
① 训练数据是公开集（出处待补），**无自采**；② YOLOv8n 架构来自 Ultralytics；
③ `nohelmet` 类只有 49 图 / 94 框，长尾学不动（AP 0.011），判定靠几何兜底。

> **为什么不是 YOLO11：** 两个权重都是 YOLOv8 结构，`.pt` 不跨版本兼容，换架构等于丢权重
> 重新训，并连带重扫判定阈值、重验 ONNX 一致性；实测收益只有 6% 耗时（同规模 CPU
> 41.4 vs 44.2 ms）。完整账见 README 4.2。

为什么还要留 COCO 人体模型：五类权重虽然自带 `person`，但在密集、远距离场景下召回
不如专门的 COCO 人体模型。两路 person 合并时**必须丢掉装备模型那一路**
（`DualDetector.drop_equip_person`），否则同一人算两遍——实测 person AP 会从 0.797 掉到 0.655。

## 三、为什么要 .pt 和 .onnx 两份

| | `.pt` | `.onnx` |
|---|---|---|
| 运行时依赖 | torch（本机 1.99 GB） | onnxruntime ≈ 80 MB |
| 用途 | 训练、评测、重新导出 | **部署运行**（任意电脑） |
| CPU 单帧 | 138 ms | **≈46 ms** |
| 输出一致性 | — | 已验证：标签完全一致，置信度最大偏差 0.001 |

> 单帧耗时的唯一口径：`evaluate_real.py` 在 100 张测试集上的均值（含前后处理）。
> **53.5 ms 是 v1.1.0 之前未锁 `onnxruntime` 版本时的旧数，已作废**；
> 当前 ONNX-CPU ≈46 ms（p95 ≈49）、torch-GPU ≈22 ms（p95 ≈25）。
> ONNX 这一版把三个模型改成共享预处理 + 并发执行，输出逐框不变，见 `docs/技术口径.md` 3.2。
> 见 [`技术口径.md`](技术口径.md) 第三节。

`.onnx` 是从 `.pt` 导出的快照。**改了 `.pt` 必须重导 `.onnx`**——本轮就踩过这个坑：
`vest.pt` 更新后 `vest.onnx` 还是上一代，验收脚本一跑就抓出来了（torch 0.816 vs onnx 0.716）。
这种错误不会报错，只会让"可移植版"悄悄跑错模型。

## 四、怎么拿到权重

**v1.1.0 起权重随仓库分发** —— `models/` 已放行（约 105 MB，单文件最大 44.72 MB），
克隆下来就有，不用再到处找。拿到先核一次指纹，确认是同一份：

```bash
python -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('models/best.pt').read_bytes()).hexdigest())"
```

只想要部署用的那一份：`models/onnx/` 三个文件就够，配套 `requirements-cpu.txt`（约 80 MB，不装 torch）。

**改了 `.pt` 必须重导 `.onnx`**：

```bash
python src/anxun/export_onnx.py
```

**自己训 vest**（另外两个是公开权重，不再需要下载）

```bash
python tools/make_vest.py                                  # 从 Chapian 数据生成 80/20 切分
python src/anxun/finetune.py --data datasets/vest_all/data.yaml \
    --init models/yolov8n.pt --name vest_aug_full --epochs 45 --aug strong
python src/anxun/export_onnx.py                            # 三个模型一起导出 .onnx
```

集齐后跑一次 `python src/anxun/verify_all.py`：
仓库自带权重、评测集与演示素材时是 **62 项：PASS 59 · FAIL 0 · SKIP 3**（跳过的 3 项是 helmet_p2 训练集 2 项 + 1080p 复验素材 1 项）；
把 `tools/fetch_helmet_p2.py`、`tools/make_1080_stream.py` 跑一遍补齐，则是 **62 项全 PASS**。

## 五、已知限制（不藏）

| 项 | 实测 | 说明 |
|---|---|---|
| helmet AP@0.5 | **0.7545** | v3.0.0 自训权重（v2.2.0 的第三方权重是 0.5645） |
| vest mAP@0.5 | **0.5214** | 五类权重自带 vest，训练图从 100 张涨到混编集，误报/漏报同步改善 |
| 域匹配 | 偏弱 | 训练/测试数据均为境外工地照片，与国内车间存在域差 |
| 小目标 | 有限 | 安全帽在 640 输入下仅 30–50 px，远距离人员会被判「无法判定」 |

**结论**：v3.0.0 的检测层已经追上来了（helmet AP +19 点、假框减半），但业务误报从 6.12% 涨到 10.20%——天花板已经从「模型不行」变成「判定阈值与漏报的权衡」。
