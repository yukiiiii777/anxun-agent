一、数据流设计

先把数据怎么流转画清楚，搭平台的时候照着填，不会乱。

摄像头 / 视频文件→ 抽帧→ 检测模型 API→ ② 视觉感知→ ③ 隐患研判→ ④ 工单闭环→ 复查归档

旁边三条支线：① 巡检规划在每日开始时产出计划，决定拍哪里；⑤ 合规问答随时被 ③④ 调用取法规依据；历史数据回流给 ① ③，让风险加权和 L 值算得出来。

架构上的一个关键决定：检测模型必须封装成独立的 HTTP API，而不是塞在 Agent 内部。
好处有三：① 平台迁移时不重写（Coze 换 JoyCode 只换调用地址）；② 评委能直接访问这个接口验证；③ 模型迭代不影响上层。

二、三个核心数据结构

不要用散落的变量，一开始就定成三张表。后面生成工单、算 L 值都靠它们。

2.1 区域表 regions

字段类型说明
region_idstring区域编号，如 A-03
namestring区域名称，如「3 号车间东侧通道」
risk_classenum动火 / 危化品 / 高处 / 有限空间 / 普通
ownerstring责任班组长
violation_30dint近 30 天违规次数（用于 L 值计算）

2.2 事件表 events

字段类型说明
event_idstring事件编号
region_idstring关联区域
tsdatetime发生时间戳
violation_typeenum未戴安全帽 / 未穿反光背心 / 未戴护目镜 / 通道占用
confidencefloat检测置信度
evidencestring证据图路径或帧号
level_L / level_S / risk_Rint风险矩阵三要素
gradeenum红 / 橙 / 黄 / 蓝

2.3 工单表 tickets

字段类型说明
ticket_idstring工单编号
event_idstring关联事件
requirementstring可验证的整改动作
assigneestring责任人
due_atdatetime整改时限
review_atdatetime复查时间
statusenum派单 / 整改中 / 待复查 / 已闭环 / 逾期
这三张表就是「结果解读」和「价值量化」两页 PPT 的数据来源。没有表，你只能讲感觉；有表，你能出图表：违规趋势、闭环时长分布、逾期率。评委看图表比看文字快十倍。

三、模型训练口径

这部分的重点是指标能报得出来、报得诚实。评委不会追问 mAP 小数点，但一定会问「误报怎么办」。

3.1 类别设计

类别必要性说明
person必须人员基准框，所有判定都以它为参照
helmet必须安全帽，核心判定对象
vest建议反光背心，扩展判定维度
goggles可选防护眼镜，目标小、难检测，时间不够就砍

四类起步，两类保底。person + helmet 两个类别就能撑起完整演示，不要一开始铺太大。

3.2 数据增强：每种都对应一个现场问题

增强方式针对的现场问题怎么做
亮度/对比度扰动车间光线不均、逆光、夜间Gamma 变换 + 直方图均衡，模拟弱光
随机遮挡设备遮挡、多人重叠Random Erasing，遮挡比例 10–30%
多角度翻转 + 旋转摄像头安装角度不同水平/垂直翻转 + 小角度旋转
尺度缩放远近不同的监控距离随机缩放 + Mosaic
运动模糊人员走动造成拖影运动模糊核，低概率施加
PPT 上一定要这样写：「针对车间逆光场景，采用 Gamma 变换模拟弱光；针对多人遮挡，采用 Random Erasing 遮挡 10–30%。」
而不是「我们做了数据增强」。说出每种增强对应哪个现场问题，证明你下过现场；只说做了增强，证明你会调库。

3.3 指标口径（答辩要能张口就来）

指标目标值为什么重要
mAP@0.5≥ 0.85常规检测指标，说明模型可用
误报率≤ 10%比 mAP 更该强调——工业场景误报会让人直接关掉告警
漏报率≤ 5%安全场景漏报后果更严重，要主动说
单帧推理耗时≤ 50 ms证明能做实时，不是离线跑批

不要报 99% 这种数字。工业检测报 99% 反而让评委怀疑你不懂现场。报一个真实但不完美、并能解释误差来源的数字，可信度高得多。

四、平台搭建步骤

4.1 五步搭完（扣子 / Coze 路径）

  1. 部署检测 API：模型封装成 HTTP 服务（本地可先用内网穿透临时对外），接口定义为 POST /detect，入参图片 URL 或 base64，出参检测框列表。
  2. 创建 Bot：新建一个 Bot，把人设和 ② 视觉感知 Agent 的提示词贴进去。
  3. 挂知识库：上传法规与标准 PDF，按条款切分，挂到 ⑤ 合规问答 Agent。
  4. 建工作流：把风险矩阵计算做成工作流节点（L 值查表 → S 值查表 → 相乘 → 映射等级），避免让模型算乘法。
  5. 发布拿到链接：发布为「Bot 商店 / 公开访问」，把链接写进 PPT 第 19 页。
第 4 步最容易做错：很多人让大模型自己算 L×S，结果同一个违规两次算出不同等级。必须做成工作流里的确定性节点，输入同样的 L 和 S，永远输出同样的等级。这是可复现性的底线，也是答辩时敢让人当场重算的底气。

4.2 如果赛区强制 JoyCode

把检测 API 原样部署到 JoyCode 的云函数或容器；上层用一个简单前端页面调三个接口（检测、定级、生成工单）。因为业务逻辑都写在提示词和 API 里，迁移只涉及界面，2 天能完成。这也是第一节强调「模型独立成 API」的原因。

五、6 分钟视频分镜

按镜头写，录的时候照着一镜一镜拍，比自由发挥快得多。

0:00
黑屏白字 · 3 秒
屏幕中央一行字：「一个安全员，管不了三个车间。」
旁白：法规要求每个作业人员正确佩戴劳动防护用品。但现实是——检查的人一走，帽子就摘了。
0:20
现场照片 + 数据条
几张厂区实拍（没戴帽/通道堆放），叠加「人工巡检覆盖率」「检查前后合规率差」的对比数字
旁白：不是工人不怕，是没人盯着。安全员一个人管几个车间，覆盖不过来。
0:45
方案总览 · 架构图
五个 Agent 的横向链路图，逐个亮起
旁白：安巡 Agent 把这条链路交给五个角色协同——规划、看、判、派、查。
1:30
数据与知识库
公开数据集规模 + 自采场景照片 + 四层知识库结构
旁白：公开数据集保证泛化，自采数据保证落地。法规知识库让每一条结论都能追到条款。
2:30
演示第一段 · 识别（40 秒）
真实画面播放 → 检测框实时出现 → 未戴帽者被标红 → 置信度显示
旁白：画面里三个人，两个戴了，一个没有。系统给出 0.87 的置信度。
3:10
演示第二段 · 定级（30 秒）
同一违规在不同区域被算出不同等级：普通区 R=9 橙色 / 高处作业区 R=16 红色
旁白：同样是没戴帽子，在高处作业区是立即停工的红色风险，在普通车间是当日整改的橙色。
3:40
演示第三段 · 闭环（40 秒）
工单自动生成 → 责任人、2 小时时限、可验证整改动作 → 条款依据弹出
旁白：工单不是「加强管理」，是「补发 3 顶安全帽并登记发放记录」。依据是 XX 法第 X 条。
4:20
技术判断 · 为什么放弃火焰检测
语义判断 vs 存在性判断的对比图
旁白：我们试过火焰检测，放弃了。那是语义问题，误报高到不可用；这是存在性问题，有明确答案。
5:00
价值量化 + 创新点
三个指标的前后对比条形图
旁白：覆盖率、闭环时长、真实合规率。
5:40
收尾 · 局限性
一页列明当前不足与下一步
旁白：当前只在单一厂区验证，跨场景泛化仍需数据；我们下一步做的是……
录制要点：① 演示三段务必连续录屏，不要剪碎——评委要看的是「一次交互里跑通全链路」；② 别念 PPT，用讲的；③ 画中画人像，观感比纯录屏好一档；④ 全程语速平稳，6 分钟不要赶，官方要求是「不超过」，不是「必须满」。

六、提交前自查清单

6.1 格式硬性要求

  • PPT ≤ 20 页，16:9，≤ 50 MB
  • 视频 MP4，≤ 6 分钟，≤ 300 MB
  • 压缩包 ≤ 200 MB，只有一个文件（不接受多文件上传）
  • 命名格式：命题领域-学校-队长姓名-作品名称
  • PPT 第 19 页含可点击的 Agent 链接（自己点一遍确认能打开）
  • PPT 第 19 页含 ≥ 3 个提示词示例及对应输出截图

6.2 内容完整性（对照官方六章）

  • 作品背景与说明：有团队分工、有参考来源
  • 数据收集与处理：≥ 2 个数据渠道，说明权威性与时效性；有预处理流程图
  • 分析过程：有方法选择依据；有思维导图（官方点名要求的形式）
  • 创新性与独特视角：1–2 个创新点 + 跨学科视角
  • 结果解释与建议：结果价值、2–3 条不足与建议、风险识别与应对
  • 应用结果呈现：对话界面截图 + 提示词 + 链接

6.3 技术核查

  • Agent 链接在非本人设备上能打开并正常交互
  • 演示用的案例数据已固定，不会因重跑而变
  • 风险定级可复现：同一输入连跑三次，等级一致
  • 法规条款引用能在原文中逐字查到
  • 输出中不含任何人脸身份信息（自查一遍截图）
  • 模型指标是自己实测的，不是引用别人的

6.4 答辩准备

  • 能一句话说清「为什么放弃火焰检测」
  • 能背出误报率与漏报率，并对「误报怎么办」有分层回答
  • 准备好「这不就是摄像头+AI 识别吗」的反驳
  • 准备好「商业上谁付钱」的回答
  • 准备好「工人抵触隐私」的伦理立场
最后一条提醒：把提交死线设成 11 月 9 日。官网以最后一次上传覆盖为准，但 10 号晚上系统拥堵、上传失败没有任何补救通道。多留一天，比多改一版重要。
