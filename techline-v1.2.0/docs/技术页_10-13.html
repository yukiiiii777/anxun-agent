怎么读这组数：公开权重 yolov8s-hard-hat 直接推理的结果，没在我们的数据上微调， 域不匹配导致置信度整体偏低，大量样本落进 0.20–0.30 灰区——这是权重的问题，不是判定链的问题。
六步优化：面积阈值按画面占比换算 → 裸头框作反向证据 → CONF_FINAL 0.60→0.40→0.30 → IOU_MIN 0.30→0.25 → 装备框面积上限 1.6→3.0 → 几何闸门 MIN_ASPECT 1.2→0.9。 第④步拿 1 个点漏报换 4 个点误报（误报首次达标）；第⑤步这个模型把帽框画得偏大，1.6 会把真戴帽的框整条拒掉， 放宽后误报 7.1%→5.1%、漏报不变；第⑥步逐张看过 4 例高宽比告警，蹲姿 2 例恢复判定， 漏报 24.7%→22.6%，误报一例没涨。
微调实验（已做，暂不采用）：80 张训练后 helmet AP 0.579→0.766，但误报/漏报反而变差—— 置信度整体下移，真帽子掉到检测阈值以下。AP 与业务指标之间隔着一层校准，数据不够时不能硬换。
扫参 6 组：换 yolov8m 掉 14 个点（跨数据集权重口径对不上），提到 960 掉 3.4 个点且慢 2.2 倍。 s@640 已是这批权重的最优点；要多带路数可切 480，快 35%、7 路/进程，代价是误报升到 15.8%。
设备：上 RTX 5060 后单帧 138 → 22.9 ms（6 倍），三个精度指标一字不差——换设备只影响速度、不影响判定。

为什么放弃火焰检测，改做安全帽

同一个赛题下我们比较了三个方向。放弃不是做不出来，是做不稳。
火灾 / 烟雾检测PPE 穿戴检测（选定）
任务本质语义判断 —— 「像不像火」存在性判断 —— 「头上有没有」
主要干扰源蒸汽、粉尘反光、红色物料、焊接弧光遮挡、光照（都可控）
精度天花板换一个厂区就掉一大截类别稳定，可做高
演示风险灯光一变就翻车，录屏不可复现同一条素材录几遍结果一致
误报代价高（一次误报就是一次停产疏散）低（补一顶帽子，成本可忽略）
能否闭环到工单难，火情不是「限期整改」的事能，责任人 / 时限 / 复查都成立
在工业场景里，宁可做一个可靠的小任务，也不做一个不可靠的大任务。
我们要证明的不是模型能识多少类，而是识别结果能不能变成一条有人负责的工单。

创新点与跨学科视角

两个创新点，各配一句能被记住的话。
创新点 01

感知闭环：让 Agent 有眼睛

多数 Agent 作品停在「对话」。我们把摄像头接进决策链：看得见（双模型串联：人体 + 装备）→ 判得准（四态判定 + 正反证据融合：有帽框算戴、裸头框算没戴、两者都有转人工）→ 落得下（工单 + 状态机）。 并且为实时视频专门做了三级触发——抽帧 / 帧差 / 无人门控，合成素材上前向从 240 降到 39（省 84%）； 换成 1080p 真实照片素材复验时发现阈值 3.0 会被机位晃动击穿（节省跌到 39%），调到 10.0 后回到 86%， 因为现场的浪费从来不是「模型慢」，而是「算了不需要算的帧」。

「看得见 → 判得准 → 落得下」
创新点 02

定级有据：等级不由大模型拍脑袋

同样的「没戴帽子」，在高处作业平台是 R=16 立即停工的红色风险，在原料库装卸区是 R=3 加强关注的蓝色。 定级走 R = L × S 查表 + 法规条款映射，纯确定性计算，同一输入连跑三次结果一致，敢让评委当场重算。

「告警是一条通知，工单是一个责任」
