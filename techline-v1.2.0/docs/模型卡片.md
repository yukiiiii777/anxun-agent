# 模型卡片 · 安巡 Agent 技术线 v1.2.0

> 技术线交付物之一是「**能跑的模型**」。本卡片说明三个模型各是什么、从哪来、怎么验证它能跑。
> 全部数字由脚本核对，重跑 `python src/anxun/verify_all.py` 即可复现。

## 一、三个模型

| 权重 | 用途 | 结构 | 输出类别 | 体积 | 来源 | 自训 | 许可证 |
|---|---|---|---|---|---|:---:|---|
| `models/yolov8n.pt` | 人体检测 | YOLOv8n（COCO 80 类） | `person` | 6.55 MB | `kadirnar/yolov8n-v8.0`（HF 镜像） | ❌ | AGPL-3.0（上游） |
| `models/best.pt` | 安全帽检测 | YOLOv8s 微调 | `Hardhat` / `NO-Hardhat` | 22.49 MB | `keremberke/yolov8s-hard-hat-detection`（HF 镜像） | ❌ | AGPL-3.0（上游） |
| `models/vest.pt` | 反光背心检测 | YOLOv8n 微调 | `vest` / `no_vest` | 6.26 MB | **本项目自训**：Chapian train 100 张，强增强，45 轮 | ✅ | 随本项目 |

**只有 `vest.pt` 是自训的。** 对外表述用「公开权重 + 自训背心模型组成三模型串联」，
不要说「我们训练了安全帽模型」——两个前序权重都是第三方发布，我们做的是选型、串联与评测。

> **为什么不是 YOLO11：** 三个权重都是 YOLOv8 结构，`.pt` 不跨版本兼容，换架构等于丢权重
> 重新训，并连带重扫两套判定阈值、重验 ONNX 一致性；实测收益只有 6% 耗时（同规模 CPU
> 41.4 vs 44.2 ms）。完整账见 README 4.2。

只用三个模型串联，是因为**公开的安全帽权重没有 person 类**——单模型跑出来每张图都是「0 人」，
判定链第一步就断了。拆开之后任何一个模型都能独立更换。

## 三、为什么要 .pt 和 .onnx 两份

| | `.pt` | `.onnx` |
|---|---|---|
| 运行时依赖 | torch（本机 1.99 GB） | onnxruntime ≈ 80 MB |
| 用途 | 训练、评测、重新导出 | **部署运行**（任意电脑） |
| CPU 单帧 | 138 ms | **72.7 ms** |
| 输出一致性 | — | 已验证：标签完全一致，置信度最大偏差 0.001 |

> 单帧耗时的唯一口径：`evaluate_real.py` 在 100 张测试集上的均值（含前后处理）。
> **53.5 ms 是 v1.1.0 之前未锁 `onnxruntime` 版本时的旧数，已作废**；
> 当前 ONNX-CPU 72.7 ms（p95 82.4）、torch-GPU ≈22 ms（p95 ≈25）。
> 见 [`技术口径.md`](技术口径.md) 第三节。

`.onnx` 是从 `.pt` 导出的快照。**改了 `.pt` 必须重导 `.onnx`**——本轮就踩过这个坑：
`vest.pt` 更新后 `vest.onnx` 还是上一代，验收脚本一跑就抓出来了（torch 0.816 vs onnx 0.716）。
这种错误不会报错，只会让"可移植版"悄悄跑错模型。

## 四、怎么拿到权重

**v1.1.0 起权重随仓库分发** —— `models/` 已放行（约 105 MB，单文件最大 44.72 MB），
克隆下来就有，不用再到处找。拿到先核一次指纹，确认是同一份：

```bash
python -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('models/best.pt').read_bytes()).hexdigest())"
```

只想要部署用的那一份：`models/onnx/` 三个文件就够，配套 `requirements-cpu.txt`（约 80 MB，不装 torch）。

**改了 `.pt` 必须重导 `.onnx`**：

```bash
python src/anxun/export_onnx.py
```

**自己训 vest**（另外两个是公开权重，不再需要下载）

```bash
python tools/make_vest.py                                  # 从 Chapian 数据生成 80/20 切分
python src/anxun/finetune.py --data datasets/vest_all/data.yaml \
    --init models/yolov8n.pt --name vest_aug_full --epochs 45 --aug strong
python src/anxun/export_onnx.py                            # 三个模型一起导出 .onnx
```

集齐后跑一次 `python src/anxun/verify_all.py`：
仓库自带权重、评测集与演示素材时是 **47 项：PASS 44 · FAIL 0 · SKIP 3**（跳过的 3 项是 helmet_p2 训练集 2 项 + 1080p 复验素材 1 项）；
把 `tools/fetch_helmet_p2.py`、`tools/make_1080_stream.py` 跑一遍补齐，则是 **47 项全 PASS**。

## 五、已知限制（不藏）

| 项 | 实测 | 说明 |
|---|---|---|
| helmet AP@0.5 | 0.565 | 用的是第三方权重，未在现场数据上微调；两轮公开数据微调均失败（见 README 5.4/5.5） |
| vest mAP@0.5 | 0.452 | 仅 100 张训练数据，小验证集选轮次噪声极大 |
| 域匹配 | 偏弱 | 训练/测试数据均为境外工地照片，与国内车间存在域差 |
| 小目标 | 有限 | 安全帽在 640 输入下仅 30–50 px，远距离人员会被判「无法判定」 |

**结论**：这套模型能跑、指标可复现，但准确度的天花板不在结构、在权重与数据的域匹配。
