# 变更日志

## v1.2.0 — 2026-11-02

这一版不碰模型、不动指标。主线是**把交付口径收敛成一套**：此前同一份作品并存着两套阈值、
三个耗时版本、两套类别口径，评委当场就能撞出来。版本号进一位，是因为交付物里新增了三份文件
（口径表 / 置信区间 / 三张图），口径本身也变了。

### 判定阈值：从「写死在代码里」改成「一份配置，两个名字」

- 新增 **`config/thresholds.json`**：阈值唯一事实来源，含两套 profile ——
  `measured`（0.30 / 0.20 / IoU 0.25，交付与评测默认）与 `conservative`（0.60 / 0.40，演示用）。
- `rules_engine.py` 启动时加载配置，模块常量由 `apply_profile()` 赋值；`pipeline.thresholds()`
  改为读 `profile_snapshot()`，不再各存一份。`/api/scenes` 因此会带上当前口径名。
- 切换方式：`ANXUN_RULES_PROFILE=conservative`、`--profile conservative`（`app.py` / `evaluate_real.py`）
  或代码内 `apply_profile()`。
- `evaluate_real.py` 把口径写进结果 JSON（`config.rules_profile`）；`data/metrics_real.json`、
  `metrics_onnx.json` 已补标 `measured`。
- **实测回归**：重跑 `evaluate_real.py` 得到 0.6808 / 5.10% / 22.58% / 72-21-5-93，与改造前逐位一致。

> 配套动作：其它文档里若还留着 0.60 / 0.40 的旧阈值表，请直接换成
> [`docs/技术口径.md`](docs/技术口径.md) 第一节。

### 耗时口径：一个数，四个条件

- README 2.1 与 `docs/模型卡片.md` 里的 **53.5 ms 作废**（未锁 `onnxruntime` 版本的旧数），
  统一为 ONNX-CPU **72.7 ms**、torch-GPU **22.9 ms**（均为 `evaluate_real.py` 在 100 张上的均值）。
- 启动自检的 8.8 / 31.7 ms、批处理的 6.9 / 7.1 ms 明确标注为「非指标口径」。

### 指标：补置信区间，把「达标」说准

- 新增 `tools/metric_ci.py` → `data/metrics_ci.json` + **`docs/指标置信区间.md`**（自动生成）。
- 结论：误报率 5.1% 的 95% 区间 **2.2–11.4%**，上界越线 → 只能说「点估计达标」；
  漏报率 22.6% 的区间 **15.3–32.1%**，下界仍高于 5% → 差距不是样本量造成的。

### 类别体系：一张表说清三层

- 新增 **`docs/技术口径.md`** 第二节：数据集 9 类 → 模型输出 → 引擎类别 的完整映射，
  并写明 **goggles / boots / gloves 有标注但没有模型**，PPT 不能写「四类检测」。
- README 第四节标题下的「双模型串联」改为三模型，补来源与「是否自训」列，
  给出答辩措辞：不能说「我们训练了安全帽模型」。

### 可复现性

- `datasets/*/data.yaml` 全部去掉绝对路径，改为相对 yaml 所在目录；生成脚本
  （`make_vest.py` / `make_mix.py` / `fetch_helmet_p2.py` / `finetune.py`）同步改，重跑不会写回 `D:/...`。
- 顺带修好两个本来坏着的配置：`ppe_test/data.yaml` 指向不存在的 `images/`（实际是 `train/images`、
  `test/images`），`helmet_p2/data.yaml` 的 `val` 写成 `val/images`（实际是 `valid/images`）。
- `verify_all.py` 新增 `--fetch`：一条命令补齐 3 项 SKIP 依赖的大件（约 110MB），不用再手翻 README。

### 验收脚本：37 → 43 项

新增 6 条硬检查，专防口径分叉：

| 新增检查 | 拦什么 |
|---|---|
| `data.yaml 不含本机绝对路径` | 换台机器 clone 下来跑不动 |
| `代码阈值与 config/thresholds.json 一致` | 有人改代码不改配置（或反着来） |
| `交付指标标注了阈值口径` | 报出去的数字说不清是哪套阈值跑的 |
| `技术页页脚标注判定阈值口径` | PPT 与代码各说各的 |
| `两套口径的判定行为符合预期` | 阈值改了但判定没跟着变 |
| `指标与风险矩阵图已生成` | JSON 有数、图上没东西 |

仓库直接跑 **43 项：40 PASS · 0 FAIL · 3 SKIP**；`--fetch` 补齐后 **43 项全 PASS**。

### 新增出图与采集工具

- `tools/plot_metrics.py` → `docs/figs/`：混淆矩阵、PR 曲线、L×S 风险矩阵，
  1280×720 直接贴 PPT 第 11 / 13 页。
- `tools/collect_selfdata.py`：现场视频 → 去重抽帧 → 可标注目录（含空标注负样本、manifest、覆盖度核对）。
  补采自那一刻起是「跑命令」而不是「写代码」。

## v1.1.0 — 2026-11-01

这一版不加架构、不换模型。主线是「把已经能跑的东西交付干净」：权重与评测集随仓库走、口径对齐、
把一处过保守的判定闸门校准回来。mAP 与误报率不动，漏报率小幅下降。

### 变更

**判定链**

- `MIN_ASPECT` 1.20 → 0.90（`rules_engine.py`）。4 例触发该闸门的样本逐张复核：蹲姿 2 例的头部
  仍落在「人体框顶部 30%」判定区内，判「无法判定」等于白丢告警；弯腰 2 例头部已偏出区域，继续不判。
- 影响：漏报率 **24.73% → 22.58%**（n=93，恢复 2 例），误报率 **5.10% 不变**，mAP@0.5 **0.6808 不变**；
  背心漏报 12.97% → 11.35%。

**交付形态**

- 模型权重入库：3 个 `.pt` + 3 个 `.onnx` + manifest（约 101 MiB）。此前仓库不含权重，
  clone 下来服务起不来、指标无法复现。`hardhat_m.pt`（49.6 MB，仅 `sweep.py` 架构对比用）仍排除。
- 评测集入库：`datasets/ppe_test/`（100 测试 + 100 训练 + 标注，14 MB，CC BY 4.0）。
  四个指标现在可在仓库内一键复现，实测与 `data/metrics_real.json` 逐位一致。
- 演示素材入库：`datasets/scenes/`（4 张，300 KB），控制台不再空白。
- 1080p 复验素材（51 MB）与 `helmet_p2` 训练集（60 MB）仍不入库，`tools/` 里的脚本可重建。

**验收脚本 `verify_all.py`**

- 新增 `skip()`：依赖没随仓库分发时记 SKIP，不计 PASS/FAIL —— 缺件和「东西坏了」分开报。
- 新增「ONNX 后端可加载并前向」硬检查（权重损坏会在这里暴露，而不是等换机器）。
- 无评测集时改用合成探针图做推理烟测，不再抛 `IndexError`。
- 新增「README 版本号与包版本一致」检查；验收报告 JSON 写入 `version` 字段。
- 当前：仓库直接跑 **37 项 34 PASS / 0 FAIL / 3 SKIP**；补齐训练集与 1080p 素材后 **37 项全 PASS**。

**依赖**

- `requirements-cpu.txt` / `requirements-gpu.txt` 全部改为精确版本，取自实测环境
  （onnxruntime 1.31.1 · ultralytics 8.4.99 · opencv-python 5.0.0 · numpy 2.5.4 · torch 2.14.1 · torchvision 0.29.1）。
  此前一直是 `>=` 软约束，是 ONNX 单帧从 53.5 ms 漂到 72.7 ms 的根因——同一模型、同一台机器，
  版本一换耗时差 40% 且无法归因。
- 两个文件都注明：改版本必须重跑 `evaluate_real.py --backend onnx` 并更新 README 2.1 的复测记录。

**文档**

- 新增 `docs/交付清单.md`：按赛题四项（能跑的模型 / 四个指标 / PPT 10–13 / 部署）逐项对照，
  并把「数据、模型、指标、部署、技术页」五块职责映射到具体文件与验证方式。
- README 2.3 重写：仓库里有什么、没什么，clone 后三步跑通。
- `docs/模型卡片.md` 权重获取一节改写（随仓库分发 + SHA256 自核）。
- 技术页 P10/P11 数字与实测对齐（混淆矩阵 72/21/5/93、漏报归因 21 例、单帧 22.9 ms），
  补第⑥步优化；P11 说明块精简，避免溢出 720px 画布。
